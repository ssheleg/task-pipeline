## Goal

task-pipeline stops meaning "one model for the whole run" and starts meaning "a model and a route per
role". The owner's order of 2026-11-23 is the recorded choice; it replaces the 2026-11-22 rule that the
session's own model authors the spec.

The promise has three parts:

1. **Paid thinking is spent only where an artefact decides something**, and there without a cap.
2. **Everything else runs on subscriptions.**
3. **Every token call is recorded** with route, model, role, cost and task. The owner sees day and month
   totals, and a warning before the estate reaches USD 5,000 a month.

Quality holds for three reasons. The thinker fixes the meanings. The writer may not change them. The
council still judges the finished text.

## Design

**Roles select the model (D1).** The role map is the operator's recorded choice. Under the existing rule, a
recorded override may change the model mid-run, so a role switch is no longer a silent swap. Task size
and stage select nothing.

| Role | Does | Route |
|---|---|---|
| `thinker` | deciding artefacts (D2's four) | Fable 5.2, API tokens |
| `writer` | the spec's text | Opus 5.5, subscription |
| `routine` | gap check, sizing, research planning, the classed question ledger (D4); S meanings (D3) | Fable, subscription session |
| `main` | build, tests, docs | Opus 5.5, subscription |
| `specialist-code`, `specialist-math` | specialist work | subscriptions |
| `validator` | panel verdicts, `research validate` | tokens |
| `judge` | the final ruling | Fable 5.2, API tokens |

The model names in this table are the owner's order as recorded in the meanings. Doctrine and code carry
role names only; the host map carries the ids.

**The spec loop, by role.**

| Step | Role | Takes | Leaves |
|---|---|---|---|
| 1. Analysis | `routine` | the request, the brief, the documents | the gaps, the size, the classed question ledger |
| 2a. Meanings (M, L) | `thinker`, by API, uncapped (D5) | the full brief, the classed question ledger, the cited documents | the meanings file (D6), one ledger record |
| 2a. Meanings (S) | `routine`, in session (D3) | the same | the meanings, no token call |
| 2b. Text | `writer`, subscription | the meanings | the spec, linked by path and hash (D7, D8) |
| 3. Research planning | `routine` | the ledger's open rows, the size | the dossier skeleton |
| 4. Research | scouts, specialists | one question each | Findings, Options, sources |
| 5. Verification | `thinker` writes the Recommendation (M, L); `validator`; the council; the scripts | the dossier and the spec | Recommendation, verdicts, `check` and `gate` |

A disagreement between writer and meanings goes back to the thinker as a question, never into the text
(D7). The council's accepted findings route by the judge's label: `meaning` to the thinker, `text` to the
writer (D14).

**Degraded thinker (D31).** The run names the gap, `routine` writes the meanings, and the spec header reads
`Thinker: degraded`. The council still runs, and R7's link still applies. A missing judge fails the round.

**Consilium (D10 to D17).**

- The panel is the five named families, one billed request each a round (D11).
- The judge is a fresh call (D12) under role `judge`.
- The cap is the panel's alone (D15). A panel over it fails before the judge (D16).
- The judge is exempt from the per-run line, like the thinker (D17).
- `summary.md` gains a "Rejected serious findings" list (D13).

**Spend accounting (D18 to D30).** One shared module owns three things:

- the call wrapper: task label check (D22), cost extraction (D18, D19), the pre-call warning (D27);
- the append (D21, D23);
- the summary (D25 to D30).

`consilium.py`, `research validate` and the thinker verb call through it. Subscription work never reaches
it (D24).

**Projection.** `month_to_date_usd / elapsed_days * days_in_month`, where elapsed days counts the current
UTC day as a whole day.

**Doctrine (D9, D33).** `references/model-tiering.md` loses "The spec's author is the session's own model"
and "The plan-then-execute profile", and gains one role section. `references/spec-protocol.md` and
`references/consilium.md` change their sentences in place. If the new words do not fit within the deleted
words, other doctrine is trimmed in the same change.

## Contracts

**Role map** (a host file; the shipped template carries placeholders the scripts refuse to call):

```json
{
  "schema": "task-pipeline-roles/1",
  "roles": {
    "thinker":         {"model": "<id>", "route": "api-direct", "key_env": "<VAR>", "endpoint": "<url>", "max_output": 0, "price": {"usd_per_mtok_in": 0, "usd_per_mtok_out": 0}},
    "writer":          {"model": "<id>", "route": "subscription"},
    "routine":         {"model": "<id>", "route": "subscription"},
    "main":            {"model": "<id>", "route": "subscription"},
    "specialist-code": {"model": "<id>", "route": "subscription"},
    "specialist-math": {"model": "<id>", "route": "subscription"},
    "validator": [
      {"family": "glm",    "model": "<id>", "route": "openrouter", "key_env": "<VAR>"},
      {"family": "kimi",   "model": "<id>", "route": "openrouter", "key_env": "<VAR>"},
      {"family": "grok",   "model": "<id>", "route": "openrouter", "key_env": "<VAR>"},
      {"family": "gemini", "model": "<id>", "route": "openrouter", "key_env": "<VAR>"},
      {"family": "astra",  "model": "<id>", "route": "openrouter", "key_env": "<VAR>"}
    ],
    "judge":           {"model": "<id>", "route": "api-direct", "key_env": "<VAR>", "endpoint": "<url>", "max_output": 0}
  },
  "estate": {"ceiling_usd": 5000, "spend_command": "<command printing Observatory's project spend JSON>", "project": "task-pipeline"}
}
```

- `route` is one of `subscription`, `api-direct`, `openrouter`, `openrouter-byok`.
- A token route (every route but `subscription`) gives `key_env`, and optionally `price`.
- `endpoint` is needed only for `api-direct`.
- An unresolved role, or a `<...>` placeholder, fails at preflight.
- File location, the validator list's form and the `estate` keys: Q4, Q5, Q8.

**Thinker call** (a new verb):

```
meanings.py write --task <label> --kind meanings|recommendation|plan-decisions|ruling
                  --brief <file> --ledger <spec or questions file> --doc <file> [--doc <file> ...]
                  --out <meanings.md>
meanings.py check <meanings.md>
```

- It takes the brief, the classed question ledger and the documents, plus a task label and the artefact
  kind (one of D2's four).
- It leaves the meanings file and one ledger record. On failure it leaves nothing but still records any
  billed usage.
- No `--max-usd` exists. The output limit is the model's maximum (Q7).
- Exit 0 written, 1 the call or the check failed, 2 usage (an unknown kind, or a missing `--task`).

**Meanings to spec:**

- The spec header carries `Meanings: <path>` and `Meanings-SHA256: <hex of the file's bytes>` (Q10).
- Every decision id in the meanings appears in the spec's Decisions with its meaning unchanged.
- The writer owns wording, order and examples only.
- `check` compares the ids `D<n>` of the meanings' Decisions with the first column of the spec's
  Decisions table.

**Consilium round** (`round-N/ledger.json`, schema `consilium-ledger/2`):

```json
{
  "schema": "consilium-ledger/2", "round": 1, "kind": "review", "cap_usd": 10,
  "runs": [{"started": "<UTC>", "finished": "<UTC>", "judge_only": false}],
  "calls": [{"id": "p1", "family": "glm", "attempt": 1, "billed": true, "parsed": true,
             "cost_usd": 0.42, "cost_source": "provider", "request_id": "<id>"},
            {"id": "judge", "attempt": 1, "billed": true, "parsed": true, "cost_usd": 1.10,
             "cost_source": "upstream", "request_id": "<id>"}],
  "panel_usd": 0.42, "judge_usd": 1.10, "spent_usd": 1.52
}
```

- The round promises at most one billed request per validator.
- It promises a judge ruling that classifies each accepted finding: `"class": "meaning"` or
  `"class": "text"`.
- Its round ledger total is never reduced by a rerun: `runs` and `calls` only grow, and the totals sum
  every call.
- `check` still demands three verdicts of three families, a parsable ruling and `panel_usd` within
  `cap_usd`.

**`research validate`:**

- It makes one call, and writes a ledger record with cost under D18 and D19.
- It gains a required `--task <label>`.
- A failed call still records nothing in the dossier. The ledger record of billed usage is still written.

**Ledger record** (one JSON line per token call, schema `task-pipeline-spend/1`):

```json
{"schema": "task-pipeline-spend/1", "at": "2026-11-23T19:12:27Z", "script": "consilium.py",
 "route": "openrouter-byok", "model": "<id>", "role": "validator", "task": "model-budget-ab",
 "stage": "3", "tokens_in": 6507, "tokens_out": 8377, "cost_usd": 0.0512,
 "cost_source": "upstream", "raw": {"cost": 0, "upstream_inference_cost": 0.0512},
 "request_id": "<provider request id>"}
```

- `cost_source` is one of `provider`, `upstream`, `estimated`, `unknown`.
- `cost_usd` is `null` exactly when `cost_source` is `unknown`.
- A request id is counted once in summaries.
- Each write is a single appended line, so concurrent agents are safe.
- No prompt or response text is stored.

**Summary verb** (`spend.py summary [--json|--md] [--at <UTC date>]`, schema `task-pipeline-spend-summary/1`):

```json
{
  "schema": "task-pipeline-spend-summary/1", "generated": "<UTC>", "day": "2026-11-23", "month": "2026-11",
  "today":         {"usd": 0, "calls": 0, "unpriced": 0, "by": {"role": {}, "model": {}, "route": {}, "task": {}}},
  "month_to_date": {"usd": 0, "calls": 0, "unpriced": 0, "by": {"role": {}, "model": {}, "route": {}, "task": {}}},
  "estate":   {"usd": 0, "source": "observatory", "lower_bound": false},
  "ceiling_usd": 5000, "percent": 0, "projection_usd": 0, "warning": "none",
  "drift":    {"ledger_usd": 0, "observatory_usd": 0, "percent": 0, "flag": false}
}
```

- `estate.source` is `observatory`, or `ledger` with `lower_bound: true`.
- `warning` is `none`, `80`, `95` or `100`.
- `drift.flag` is true above 10%.
- The JSON form is the stable interface Observatory reads.
- The pre-call warning is one line on stderr, with the level, the percentage and the projection.

Field names, verb names and streams in this section are the writer's form of the meanings' contracts
(Q4, Q15).

## Decisions

| id | decision | reason |
|---|---|---|
| D1 | Roles, not stages or task size, select the model, and the role map is the operator's recorded choice. | The order assigns models by kind of work, and the existing rule already lets a recorded override change the model mid-run. |
| D2 | The thinker is called by API for exactly four artefacts from size M up: the spec's meanings, the research Recommendation, the decisions of an L plan, and the consilium ruling. | These are the artefacts that decide; a longer list turns "key thinking" into "all thinking". |
| D3 | Size S makes no paid thinker call; the `routine` role writes its meanings in the subscription session. | A bounded change has no deciding artefact worth a token route, and S already skips the council. |
| D4 | Gap check, sizing, the classed ledger and research planning are `routine`. | They are smart but prepare decisions without making them. |
| D5 | The thinker receives the full brief, the ledger and the cited documents, never a summary, and its calls carry no token or cost cap. | The owner said "without stinting", and a starved thinker is the main quality risk of the split. |
| D6 | The meanings file is a stored artefact beside the spec with a fixed section set (goal, key features, numbered decisions, contracts, non-goals, risks, owner questions). | Meanings held only in context are lost with the session and cannot be checked. |
| D7 | The writer may not add, drop or alter a decision or a contract; a disagreement returns to the thinker as a question. | Two authors of meaning produce a spec nobody decided. |
| D8 | `spec_protocol.py check` fails an M or L spec that has no meanings reference, a stale meanings hash, or a decision id absent from the spec. | A mechanical link is the only enforceable form of D7. |
| D9 | The plan-then-execute profile and the section "The spec's author is the session's own model" are deleted and replaced by the role section. | The role map supersedes both and the word ratchet needs the room. |
| D10 | The panel is the five named validator families; a panelist of the thinker's or the writer's family is removed. | The author never sits on its own artefact's panel, and there are now two authors. |
| D11 | Each validator gets one billed request a round, with one retry only when the first attempt returned no billed usage; an unparsable answer is not retried and counts as a missing verdict. | The order says one request each, and the gate of three verdicts from three families already tolerates loss. |
| D12 | The judge is a fresh call with no thinker context. | Fable judging meanings Fable wrote is the design's weakest point, and context isolation is the mitigation available. |
| D13 | Every rejected blocker or major finding is listed with its reason in `summary.md`. | A rejected serious finding is where self-judgement would hide, so the owner must be able to see it. |
| D14 | The judge labels each accepted finding `meaning` or `text`; `meaning` goes back to the thinker, `text` to the writer. | Otherwise the writer would change meanings while fixing findings. |
| D15 | `max_usd_per_round` counts panel spend only; the judge's cost is recorded but never counted toward it, and the judge is never skipped for its own cost. | The owner ordered that Fable rules last even when paid. |
| D16 | A panel over the cap still fails the round before the judge. | A runaway panel should not be ruled on. |
| D17 | The thinker and the judge are exempt from the host's per-run line; validators and scouts stay under it. | "Without stinting" and a per-run cap cannot both bind the same call. |
| D18 | Recorded cost is `usage.cost` plus `usage.cost_details.upstream_inference_cost` when present, with both raw values kept. | The BYOK call measured on 2026-11-23 reported zero in the first field and the real cost in the second. |
| D19 | A call with no provider cost is priced from the configured price table and marked `estimated`; with no price it is recorded as `null` and counted as unpriced, never as zero. | A silent zero is the defect already observed. |
| D20 | A round ledger is append-only; `--judge-only` appends, and the round total sums all entries. | The rerun currently zeroes the panel's cost. |
| D21 | One estate ledger, a JSON-lines host file (path from an environment variable, with a default under the host's state directory), is written through a single shared script module. | Three scripts with three formats cannot be summed. |
| D22 | A token call without a task label is refused before any spend. | The order requires every call recorded with its task, and an unlabelled cost cannot be attributed later. |
| D23 | The ledger stores no prompt or response text. | People's text must not leak into an accounting file. |
| D24 | Subscription calls are not written to the ledger. | The order tracks token routes, and subscription usage has no per-call cost. |
| D25 | Day and month are UTC. | Providers bill in UTC and Observatory compares against them. |
| D26 | The ceiling figure is the sum of every project's `totalUsd` from Observatory; when Observatory is unreachable, the ledger's month total is used and labelled a lower bound. | The ceiling is estate-wide, provider-measured, and covers spend outside this skill. |
| D27 | Warnings fire at 80%, 95% and 100% of USD 5,000, printed before each token call and in the summary, together with a linear end-of-month projection. | "Approaching" needs a number and one early line is easy to miss. |
| D28 | The warning never blocks a call. | The owner asked for a warning, and a block is an authorisation rule he did not order. |
| D29 | The owner's view is Observatory, which reads the summary verb's JSON output; the Observatory-side change is a board row outside this repository. Until it lands, the summary verb prints a terminal and Markdown view. | OpenRouter's dashboard cannot see the direct Fable API route. |
| D30 | The summary shows the drift between the ledger's month total and Observatory's figure for this project, and flags it above 10%. | An accounting system nobody reconciles is not trusted. |
| D31 | When the thinker route is unavailable, the run names the gap, writes meanings with `routine`, and marks the spec `Thinker: degraded`; the council still runs. A missing judge fails the round as today. | Silent substitution is a defect under the existing doctrine, and a stalled pipeline is worse than a marked one. |
| D32 | The preflight line prints the resolved role map once, and subagents are pinned to their role's model. | "Confirm once, then stop asking" stays the mechanic; only its content changes. |
| D33 | Doctrine edits are net zero or negative in words. | The ratchet is a repository gate. |

## Risks

| risk | mitigation or detector | refuted when |
|---|---|---|
| Self-judgement: Fable rules on meanings Fable wrote | D12, D13 and the blind panel of five other families | the judge's rejection rate for blocker findings on thinker-authored specs is clearly higher than on other artefacts |
| Quality loss in the split: the writer flattens or drifts from the meanings | D7, D8, D14 | the first five M specs under the split show more accepted blocker or major findings in round 1 than the last five before it, or `meaning` findings are routinely caused by the text |
| Thinker scope creep | D2's closed list | thinker spend exceeds half of monthly token spend without a matching rise in deciding artefacts |
| Under-recording: a token call outside the shared module escapes the ledger | drift above 10% (D30); R14's static test | |
| Refusal friction: D22 stops ad hoc runs | accepted | |
| Estimated prices go stale | the unpriced and estimated counts are shown, so the owner can discount the total | |
| Observatory lag: provider figures trail by hours, so the warning can be late near the ceiling | the ledger fallback and the projection reduce it but do not remove it | |
| Thin panel: one request each with five validators leaves a margin of two failures | D11's retry on unbilled failure | |
| Ratchet: the role section may not fit within the deleted words | other doctrine is trimmed in the same change (D33) | |

## Rollout

1. **The shared spend module**, with the ledger record, cost extraction (D18, D19), the task label refusal
   (D22) and the append. `consilium.py` and `research validate` write through it. The round ledger becomes
   append-only (D20).
2. **The role map and its template**, with preflight resolution and refusal of placeholders.
3. **The thinker verb and the meanings check.** `spec_protocol.py check` enforces D8 for M and L from this
   release (Q14).
4. **The consilium changes**: panel, retry, fresh judge, labels, the rejected-findings list, and the
   panel-only cap.
5. **The summary verb and the ceiling warning**, reading Observatory with the ledger fallback.
6. **Doctrine**, net zero or negative in words: `model-tiering.md`, `spec-protocol.md`, `consilium.md`.
   Then the version surfaces and `CHANGELOG.md`. The release is a minor version, tagged after `npm test`
   is green on the tagged commit.
7. **The board row to Observatory** (D29), asking it to read `task-pipeline-spend-summary/1`. The row id
   goes in the handoff.

Rollback: revert the release. The ledger file is additive host state; it stays and is read again on the
next release. After release, `spend.py summary` runs once on the host. Its estate source must read
`observatory`, and its drift line must be present.
