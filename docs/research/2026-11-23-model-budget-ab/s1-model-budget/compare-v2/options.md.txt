# Two candidate specs for the same brief

## Option X

# Spec: model and token budget by role in task-pipeline

Size: M

## Goal

Bring task-pipeline to the owner's order of 2026-11-23, which replaces the 2026-11-22 rule that the spec's author is the session's own model.

- Paid-by-token calls to the strongest model (the `thinker`, Fable 5.2 on the owner's estate) carry only the thinking that decides something, and carry it without a cap.
- The spec's text is written by a subscription `writer` (Opus 5.5 on the owner's estate) from the thinker's meanings.
- Decision validators answer by tokens, one request each, and the thinker gives the final verdict.
- Every token call is written down with route, model, cost and task; the owner sees a day and month summary and a warning as the estate nears USD 5,000 a month.
- Spec quality does not drop.

## Scope

In:

- A host role map (`roles.json`) and a shipped template.
- A new verb `spec_protocol.py meanings` (the thinker call) and trace rules in `check` and `gate`.
- `consilium.py`: one request per panelist, judge equals thinker, real cost under BYOK, a `--judge-only` rerun that keeps the panel's cost, `--task`, `--meanings`.
- `spec_protocol.py research validate`: cost, task, one request.
- A new stdlib module and CLI `scripts/spend.py`: the only place a model HTTP call is made, the host spend ledger, summaries, the ceiling warning.
- Doctrine edits in `model-tiering.md`, `spec-protocol.md`, `consilium.md`, inside the word ratchet.

Out:

- Changes inside Observatory. This spec defines the file Observatory reads; ingesting it is a board row in that repository.
- Tracking subscription usage. The order tracks token routes.
- Native vendor protocols. Only OpenAI-compatible chat completions is supported in this release.
- Merging ledgers across hosts.
- `pipeline.example.json` stage tokens (`default`, `inherit`) and `plan_audit.py`, which stay as they are.
- A hard stop at the ceiling (see Q2).

Assumption on paths: the doctrine directory is the one holding `model-tiering.md`, written `references/` below. Scripts live in `scripts/`, templates in `assets/`.

## Design

### 1. Review of call sites

Today's column is taken from the brief and the three doctrine files.

| # | Call site | Today | Target |
|---|---|---|---|

| 2 | Definition, stages 2 to 3 | the session's model writes the spec | meanings by the `thinker`, tokens; text by the `writer`, subscription |
| 3 | Research planning | the author | the scout questions are the `research` list of the meanings; the skeleton is `routine` |

| 6 | `research validate` | one model, any OpenAI-compatible route; usage recorded, no cost | tokens, one request, cost, task, spend row |

### 2. The role map

One JSON file per host (Contracts C1) names routes, roles, prices and spend settings. The repository ships only a template with placeholders, so no model id is hardcoded. The roles are `thinker`, `writer`, `routine`, `worker`, `specialist-code` and `specialist-math`. Panelists and the judge stay in the council's own configuration.

- **In force.** The split is in force when the resolved file is not the shipped template and defines `thinker` on a route whose `billing` is `tokens`. With no map, or the template only, the previous behaviour holds: one model does everything, `gate` asks for no meanings, and `meanings` refuses to call.
- **Subscription roles.** Scripts never call them. The orchestrating session starts a subagent pinned to the role's model through the harness's model override. If the session already runs on the role's model, it does the work itself.
- **A role the harness cannot start.** This is a named limitation recorded in the brief, under the existing rule for unsupported capabilities, and never a silent swap.
- **Choosing a role.** Does the output decide something a later stage builds on? Then `thinker`. Is it the artefact itself (text, code, tests, a search)? Then `writer`, `worker` or a specialist. Is it judgement that decides nothing (a recheck, a merge, a diff review)? Then `routine`.

### 3. Meanings and text

`spec_protocol.py meanings <spec.md>` builds one request from the brief and the inputs, sends it to the `thinker`, and writes `<spec stem>.meanings/meanings-<N>.json`. N is one more than the highest existing revision.

- **Content.** The meanings are the decisions: goal, size, items (each one checkable statement with a basis; a decision also names what it rejected), the classed question ledger, the research questions, and what could not be decided.
- **Reruns.** The verb is rerun whenever something new must be decided: after research (the dossier as `--input`), after a council ruling (`judge.json` as `--input`), after a writer gap. The previous revision is passed as `--input`. The prompt requires stable ids for unchanged items and a `retired` list instead of id reuse.
- **No stint.** The verb has no cost cap and no call limit.

The writer receives the latest meanings file, the brief, the dossier and the section list for the size. It writes every owed section and decides nothing.

- **Headers.** The spec carries `Author: <family>/thinker`, `Writer: <family>/writer` and `Meanings: <relative path> sha256:<first 16 hex of the file>`.
- **Tags.** Every requirement line and every row of the Decisions table carries at least one tag `[M<n>]`. Every non-retired item id appears at least once in the spec.
- **Gaps.** Anything the writer finds undecided goes into `<spec stem>.meanings/gaps.md`, one line each, and back to the thinker as `--input`. The writer never fills a gap.

When the spec has a `Meanings:` line, `check` fails on any of:

- the cited file is missing, or the hash prefix does not match;
- a higher revision exists in the directory (the text is stale);
- an item id that is not retired is not cited;
- a tag names an unknown or retired id;
- a line matching `^\W*REQ-\d+`, or a data row of the table under `## Decisions`, has no tag;
- the `Writer:` line is missing;
- `gaps.md` exists, is not empty, and its current sha256 is not among the `inputs` of the cited revision.

Degraded path: when the thinker's token route cannot be used (no key, provider down), the meanings may be produced in a subscription session and registered with `meanings --from-file <json> --reason "<text>"`. The same validation applies, and the envelope records `route: "subscription"` and `degraded`. No request is made, no spend row is written, and `check` prints a warning naming the reason.

### 4. The council

- **One request each.** `consilium.py` calls `spend.post_chat` once per panelist per round. A failed, timed-out or unparsable answer is saved raw, yields no verdict, and is not retried in that round. The remedy for fewer than three verdicts of three families is a new round.
- **The judge is the thinker.** The judge is still read from the council's configuration. When the split is in force, `check` compares the model id in the round's judge row with `roles.thinker.model` and fails on a difference.
- **Authors off the panel.** There are now two authors. `check` fails a round where a panelist's family equals `roles.thinker.family` or `roles.writer.family`. `research validate` records such a family with the existing warning and does not count it.
- **Fidelity.** `review --meanings <file>` appends the file to the judge's user message only, under the heading `## Meanings (the author's decisions; the text must carry each one)`. The judge instruction gains one sentence: "List as a finding every meaning the text drops, weakens or contradicts." The panel stays blind to the meanings.
- **Money.** The cap `max_usd_per_round` is summed over rows with role `validator` only. The judge runs when the panel is within the cap, and `check` tests the same sum.
- **Template.** `assets/consilium.example.json` lists five placeholder panelists, one for each of the order's validators (GLM, Kimi, Grok, Gemini, Astra), and a judge placeholder. A host file listing more panelists keeps working. Two entries with the same model id are refused at load with exit 2.

### 5. The spend ledger and the cost rule

`scripts/spend.py` owns the only HTTP call to a model.

`post_chat(*, endpoint, key_env, model, messages, task, role, kind, family=None, ref=None, max_tokens=None, timeout=600, extra_body=None)`:

- performs exactly one POST and never retries;
- appends one row to the host ledger in a `finally` block, whether the call succeeded, failed or timed out;
- returns an object with `ok`, `status`, `http_status`, `content`, `finish_reason`, `usage`, `row`.

The request body is what `consilium.py` sends today to obtain `usage.cost`, plus `"user": "tp:<task>"`. When the endpoint host ends with `openrouter.ai`, the header `X-Title: task-pipeline` is added so OpenRouter's own activity view can be filtered.

The ledger:

- **Location.** `$TASK_PIPELINE_SPEND_DIR`, else `spend.dir` of the role map, else `${XDG_STATE_HOME:-~/.local/state}/task-pipeline/spend/`.
- **Files.** One per UTC month, `calls-YYYY-MM.jsonl`, append only. A row goes to the file of its own `ts`.
- **Writes.** One `write` of one line, on a descriptor opened with `O_APPEND`, under `fcntl.flock(LOCK_EX)` where `fcntl` exists.
- **Before the first request.** A verb calls `spend.ensure_ledger()`. A ledger directory that cannot be created or written is exit 2: no record, no call.
- **Content.** The ledger holds no prompt text, no answer text and no key.

The cost rule, `spend.cost_from_usage(usage, model, prices)`, returns `(cost_usd, cost_source, router, upstream)`. Here `router` is `usage.cost` and `upstream` is `usage.cost_details.upstream_inference_cost`, each a number or absent.

1. `usage.is_byok` is true: cost is `(router or 0) + (upstream or 0)`, source `router+upstream`.
2. `usage.is_byok` is false and `router` is a number: cost is `router`, source `router`.
3. `usage.is_byok` is absent: `router > 0` gives `router`, source `router`. `router == 0` with `upstream > 0` gives `upstream`, source `upstream`. `router == 0` with no positive upstream gives 0, source `router`; the summary counts it under `zero_cost_calls` when tokens were used.
4. There is no `router`, and `prices` has the model: cost is `prompt_tokens / 1e6 * input_usd_per_mtok + completion_tokens / 1e6 * output_usd_per_mtok`, source `priced`.
5. Otherwise: cost is `null`, source `unknown`.

Failed and timed-out calls:

- A call with an HTTP error and no usage records cost 0, source `none`, status `failed`.
- A timeout records `null`, source `unknown`, status `timeout`.
- A row with status `ok` and a `null` cost is a defect: `spend.py check` and `consilium.py check` fail on it.

Costs are stored rounded to six decimals.

Each `round-N/ledger.json` row is the same dict as the host row, so the two never disagree. `--judge-only` loads the existing ledger, leaves every row in place, appends the new judge row and recomputes the totals. With no ledger file it exits 2 with `no round to rerun`.

### 6. Summary and ceiling

`spend.py summary` reads the month file or files and prints the day (a UTC date) and the month. Each has calls, cost, and cost by route, by model, by role and by task, plus the estate block.

- `--write` stores `summary.json` and `summary.md` in the spend directory by temp file and rename.
- Every token-spending verb does the same write at exit, so the files are current after every call.
- `summary.json` is the contract Observatory reads (Q1).

Estate figure:

- **Source.** `spend.estate_cmd` (an argv list, on the owner's estate Observatory's `tools/spend.py project --json`) runs with a 60 second timeout. Its JSON yields `observatory_usd`: a top-level numeric `totalUsd`; else the sum of `totalUsd` over a top-level array; else the sum over the array under `projects`; else the source is unavailable.
- **Cache.** The result is cached in `estate.json` for `spend.estate_ttl_s` (default 3600). When the command fails, a cache of any age is used and marked `stale`. With no cache the source is `local-only`.
- **Value.** `estate_usd = max(observatory_usd, local_month_usd)`. The provider-side figure already contains this host's calls and may lag them, so the two are never added.
- **Fraction.** `fraction = estate_usd / ceiling_usd_month`.
- **Level.** `ok` below `warn_at` (0.80), `warn` from 0.80, `critical` from `critical_at` (0.95), `over` from 1.0.
- **Projection.** `projected_month_usd = estate_usd * seconds_in_month / seconds_elapsed`, computed from the 7th day of the month on and `null` before. `projected_over` is true when it reaches the ceiling.

Warning: once per process, before its first request, a token-spending verb prints one stderr line when the level is not `ok` or `projected_over` is true (text in C7), then proceeds. The preflight notice and the run's closing report carry the same line from `spend.py ceiling`.

Rules:

- `prices` and `spend` are optional; the defaults are those shown.
- Unknown keys are ignored.

### C2. `spec_protocol.py`

```
spec_protocol.py roles [--roles FILE] [--json]
spec_protocol.py meanings SPEC --task ID --brief FILE [--input FILE]... [--roles FILE]
                 [--max-output-tokens N] [--timeout SECONDS] [--dry-run]
spec_protocol.py meanings SPEC --task ID --from-file JSON --reason TEXT
spec_protocol.py research validate DIR --model ID --family F --endpoint URL --key-env VAR --task ID [--route NAME]
spec_protocol.py gate SPEC --board B --plan P [--allow-no-meanings]
```

`roles`:

- Prints one line per role: `role  model  route  billing`, then `split: in force` or `split: not in force (<reason>)`.
- `--json` prints `{"source": path, "in_force": bool, "roles": {...}, "routes": {...}}`.
- Exit 0 valid, 1 invalid (each defect on stderr), 2 file unreadable or not JSON.

`meanings`:

- `--dry-run` prints the resolved model, the route and the request size in bytes, makes no request and writes nothing.
- Inputs over 2,000,000 bytes in total are exit 2.
- `--max-output-tokens` defaults to the role's `max_output_tokens`, else 32000. `--timeout` defaults to 600.
- On success it prints the path written.
- Exit codes:
  - 0 written;
  - 1 the answer is not valid meanings (raw answer saved as `meanings-<N>.raw.txt`, spend row written, no JSON file);
  - 2 usage or configuration error: no task, split not in force, placeholder, key variable unset, ledger not writable;
  - 4 the request failed or timed out (spend row written).

The user message is `# Task`, the id, then `# Brief (<path>)` and each `# Input (<path>)` with the file's text.

The system message is this text:

```
You are the thinker of a specification. You decide; a writer turns your decisions into text and may not add, drop or change one. From the brief and the inputs return one JSON object and nothing else, with the keys goal, size, items, questions, research, open, retired. Each item is one decision or meaning a builder needs: a statement that can be checked, its basis, and for a decision the alternative you rejected. Decide every tactical question yourself. Leave the owner only strategy, each with a default. When an input is an earlier revision, keep the id of every item you keep, list dropped ids under retired, and never reuse an id. Write no prose sections.
```

`research validate`:

- `--route` defaults to `openrouter` when the endpoint host ends with `openrouter.ai`, else to the endpoint host.
- The stored validation record gains `route`, `cost_usd`, `cost_source`, `task`.
- A failed call still records no verdict, and now records a spend row.

`check` and `gate` keep their exit codes: the new failures use the existing failure code, and each prints one line naming the rule. `loop` prints the new Who column.

### C3. `meanings-<N>.json` (schema 1)

```json
{
  "schema": 1, "task": "T-123", "revision": 2, "created": "2026-11-24T10:00:00Z",
  "model": "<id requested>", "model_returned": "<id in the response>", "route": "tokens-main",
  "degraded": null, "spend_id": "<ledger row id or null>",
  "inputs": [{"path": "docs/briefs/x.md", "sha256": "<64 hex>"}],
  "goal": "one paragraph",
  "size": "M",
  "items": [{"id": "M1", "kind": "requirement", "statement": "...", "basis": "...", "rejected": null}],
  "questions": [{"id": "Q1", "question": "...", "class": "tactics", "answer": "...", "by": "agent", "basis": "..."}],
  "research": [{"id": "R1", "question": "..."}],
  "open": ["..."],
  "retired": ["M4"]
}
```

The script writes the envelope keys (`schema` to `inputs`); the model returns the rest. Validation:

- `size` is S, M or L.
- `items` is not empty.
- Item ids match `^M[1-9][0-9]*$`, are unique, and none is in `retired`.
- `kind` is one of `scope-in`, `scope-out`, `requirement`, `design`, `contract`, `edge`, `decision`, `rollout`, `test`, `risk`.
- `statement` and `basis` are non-empty; a `decision` has a non-empty `rejected`.
- `class` is one of the four ledger classes.
- An answer wrapped in one Markdown code fence is unwrapped before parsing.
- A `finish_reason` of `length` is invalid.

### C4. `consilium.py`

```
consilium.py review|decide <existing arguments> --task ID [--meanings FILE] [--roles FILE]
consilium.py check DIR --round N [--roles FILE]
```

- `--task` is required, or `$TASK_PIPELINE_TASK`. `--meanings` is accepted by `review` only.
- Exit codes are unchanged; a missing task is exit 2.
- `ledger.json` gains `"schema": 2`. Each call row is the C5 row. Existing keys with the same meaning are kept once; readers accept schema 1 files.
- Totals: `total_usd` is the sum of all rows; `panel_usd` is the sum of rows with role `validator`.
- `check` adds these failures, each with a one-line reason:
  - a panelist with more than one row in the round;
  - a row with status `ok` and `null` cost;
  - `panel_usd` over the cap;
  - the judge model differs from the thinker (split in force);
  - a panelist's family is the thinker's or the writer's (split in force);
  - `total_usd` is not the sum of the rows.

### C5. Spend ledger row (schema 1, one JSON object per line)

| Field | Type | Value |
|---|---|---|
| `schema` | int | 1 |
| `id` | string | 32 hex, unique |
| `ts` | string | UTC, `YYYY-MM-DDTHH:MM:SSZ`, when the call ended |
| `host` | string | hostname |
| `task` | string | matches `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` |

### C6. `spend.py`

```
spend.py summary [--day YYYY-MM-DD] [--month YYYY-MM] [--task ID] [--json] [--write]
spend.py ceiling [--refresh] [--json]
spend.py check [--month YYYY-MM]
spend.py record --task ID --role ROLE --route NAME --model ID --cost-usd X
                [--prompt-tokens N] [--completion-tokens N] [--ref PATH]
```

- `summary`: defaults are today and the current month, UTC. `--task` limits every figure to one task. Exit 0; 2 on an unreadable ledger.
- `ceiling`: `--refresh` ignores the cache. Exit 0 at level `ok`; 3 at `warn`, `critical` or `over`; 2 on a configuration error.
- `check`: exit 1 when a line is not JSON, lacks a C5 field, has status `ok` with `null` cost, has a bad task id or repeats an `id`. The file and line number are printed. Zero-cost rows that used tokens are printed as warnings. Exit 0 otherwise.
- `record`: writes a row with kind `manual`, source `manual`, status `ok`, for a token call made outside the scripts. Exit 0; 2 on a bad argument.

### C7. `summary.json` (schema 1), `summary.md`, the warning line

```json
{
  "schema": 1, "host": "h1", "generated": "2026-11-24T10:05:00Z",
  "day": {"date": "2026-11-24", "calls": 12, "cost_usd": 3.4112, "unknown_cost_calls": 0, "zero_cost_calls": 0,
          "by_route": {"tokens-main": {"calls": 12, "cost_usd": 3.4112}},
          "by_model": {}, "by_role": {}, "by_task": {}},
  "month": {"month": "2026-11", "calls": 950, "cost_usd": 412.3, "unknown_cost_calls": 1, "zero_cost_calls": 0,
            "by_route": {}, "by_model": {}, "by_role": {}, "by_task": {}},
  "estate": {"ceiling_usd": 5000, "observatory_usd": 3120.5, "local_month_usd": 412.3, "estate_usd": 3120.5,
             "source": "observatory", "stale": false, "as_of": "2026-11-24T09:40:00Z",
             "fraction": 0.6241, "level": "ok", "projected_month_usd": 4070.2, "projected_over": false}
}
```

- `source` is `observatory` or `local-only`. The `by_*` maps have the shape of `by_route`.
- `summary.md` and the plain output give the same data as text: a header line, a `Day` block and a `Month` block (total, then one line each for route, role, model and task, as `name amount (calls)`, amounts to two decimals), an `Estate` line and a `Warnings` line.
- The warning line on stderr is `WARNING spend: estate at <pct>% of USD <ceiling> (USD <estate>, level <level>, source <source>)`.
- When only the projection is over, it is `WARNING spend: projected USD <projected> this month, ceiling USD <ceiling>`.

## Edge cases

| Case | Behaviour |
|---|---|
| BYOK call, `usage.cost` 0, upstream cost present | cost is the upstream cost (rule 1 or 3) |
| No `usage` in an `ok` response, model not in `prices` | row with `null` cost; the call's result is kept; `check` fails until a price is added and the row is corrected by a `record` entry |
| Free model, tokens used, cost 0 | recorded as 0, counted in `zero_cost_calls`, no failure |
| Timeout | status `timeout`, cost `null`, no retry; counted in `unknown_cost_calls`, no gate failure |
| Fewer than three verdicts after single calls | the round fails the existing gate; a new round is run |
| `--judge-only` twice | both judge rows stay; the last parsable ruling is the ruling; the total includes both |
| Panel within the cap only because BYOK was counted as 0 | after the fix the round may exceed the cap; Rollout step 4 reviews the cap |
| Ledger directory unwritable | exit 2 before any request |
| Two processes or threads appending | one locked single-line write each; no interleaving |
| A call ending after UTC midnight on the last day | the row goes to the new month's file, by its `ts` |
| `estate_cmd` unset, failing, or returning an unknown shape | cache if any (marked stale), else `local-only`; the level is computed from the local month and the line says so |
| Observatory total below the local month total | the local total is the estate figure |
| Before the 7th of the month | no projection |
| Role map is the template only | split not in force; `meanings` exits 2; council and research verbs work as before, with `--task` and the ledger |
| Thinker answer truncated or not JSON | exit 1, raw saved, cost recorded; the agent reruns, with a higher `--max-output-tokens` if truncated |
| Spec cites revision 1 while revision 2 exists | `check` fails as stale |
| A writer adds a requirement with no tag, or cites a retired id | `check` fails and names the line |
| A spec opened before the release | `Meanings: none (<reason>)` passes `check` with a warning; `gate` needs `--allow-no-meanings` |
| The judge shares the meanings author's family | allowed by the order; the panel stays blind and of other families; the judge must rule on every finding |
| A role's model cannot be started by the harness | named in the brief; the session's model does the work; no silent swap |
| Thinker route down | `meanings --from-file --reason`; the council judge still needs the token route, and the round fails without it |

## Decisions

| Decision | Reason | Rejected alternative |
|---|---|---|
| Roles live in a host file; the repository ships placeholders | doctrine forbids hardcoded model ids; other hosts keep one model | writing Fable 5.2 and Opus 5.5 into scripts and doctrine |
| The split is a script verb plus a JSON file with ids | a meaning the text must carry can be checked mechanically | a prose handover from thinker to writer, with no check |
| Inline `[M<n>]` tags on requirements and decision rows | one regex proves coverage and blocks requirements the writer invented | a separate coverage file, which drifts from the text |
| Every size owes meanings when the split is in force | the order names the meaning of a spec with no size exemption; an S call is small | exempting size S |
| No retry for a validator, in any failure | "one request each"; a timed-out request may already be billed | one retry on transport errors |
| No automatic retry for the thinker either; reruns are explicit | every paid call is an act an agent chose and the ledger shows | a repair loop inside the verb |
| All model HTTP goes through `spend.post_chat` | a call cannot be made without its ledger row; one grep verifies it | each script writing its own ledger row |
| `--task` is mandatory | the order wants the task on every call; a default would hide spend | a default task `unassigned` |
| The cap counts validator rows only | the thinker is used without stinting; the cap exists to bound the panel | a cap on the round's total |
| The judge is checked against `roles.thinker` at the gate, not merged into one config | the council's configuration and lookup chain stay as they are | moving panel and judge into `roles.json` |
| The meanings go to the judge only | the panel judges the artefact blind; five more copies add cost and no independence | sending the meanings to every panelist |
| The thinker judges text built on its own meanings | the owner's order; mitigated by a blind panel of other families and the fidelity instruction | a judge of another family |
| The estate figure is the larger of Observatory's and the local total | provider data includes local calls and may lag them; adding would count twice | the sum of the two |
| Days and months are UTC | one boundary for all hosts and for the providers' own activity views | the owner's local time zone |
| Only OpenAI-compatible chat completions | it is what both existing callers speak | adding vendor-native protocols now |
| The warning never blocks | the order asks for a warning; a block would stop the thinking it wants unstinted | a hard stop at 100% (Q2) |

## Rollout

2. Capture fixtures with two real calls, each under USD 0.05, with `--task fixture-cost`: one through the BYOK key and one without. Store the two `usage` objects as test fixtures and confirm the cost rule reproduces the provider's figures. Capture one real output of the Observatory command as the estate fixture.
3. Ship the doctrine edits in the same release as the scripts and run the ratchet. Bump the version (1.114.0 if the version is repository-wide).
4. On the owner's estate, write `~/.config/task-pipeline/roles.json` with the real ids, routes, prices for any route that returns no cost, and `estate_cmd`. Set the council's host file to the five validators and the thinker as judge. Raise `max_usd_per_round` if the panel's real BYOK cost exceeds it, and record the new value in the release note.
5. Run `spec_protocol.py roles`, `spend.py check` and `spend.py ceiling`; all exit 0 (or 3 for `ceiling` with a correct level).
6. Canary: the first three specs of size M or L run under the split.
   - For each, record from the round artefacts the accepted blocker and major findings in round 1 (the count the pass rule already uses), the rounds to pass, and the accepted fidelity findings.
   - The baseline is the same figures from the last three council-reviewed specs before the release. If fewer exist, the baseline is called thin in the report.
   - The numbers go to the owner in one message.
   - If the canary median of round-1 accepted findings exceeds the baseline median by more than one, or a canary spec is still open after round 3, the message carries one question with the default "keep the split".
7. Open a board row in Observatory: read `summary.json` (C7) from each host's spend directory and show day, month and level.
8. Rollback: remove `thinker` from the host's `roles.json`. The split is then not in force and `gate` asks for no meanings, while the ledger and the cost fixes stay. A full rollback is a revert of the release commit.

## Goal

Every stage of task-pipeline runs on a named role, and each role resolves in host
configuration to one model on one route. Token money goes only to thinking that
decides something (the `thinker`) and to validators; everything else runs on
subscriptions. Every token call leaves exactly one ledger row, and the owner sees
day and month totals against the USD 5,000 development-mode ceiling.

This replaces the rule of 2026-11-22 ("the spec's author is the session's own
model"). Quality is held by three things: the strongest model decides every
meaning, a blind panel checks the result, and a replay test compares the new
split against the old (D28).

| Research merge | fast tier | removed; a Resolution is a decision, so `thinker` writes it |
| Stages 5 to 9 | the run's confirmed model | `worker`; code and mathematics go to `specialist-code` and `specialist-math` (subscriptions) |
| Judgment that decides nothing binding (citation rechecks, diff review) | the session | `routine` (Fable in a subscription session) |

Stages 0, 1 and 10 outside the thinker's D6 calls run on `worker` (Q20).

### Roles

| Role | Route | This host's model (host config, not doctrine) | Runs |
|---|---|---|---|
| `thinker` | api | Fable 5.2 | the D6 calls only: meanings, Recommendation, Resolution, L plan decisions, consilium verdict, revisions |
| `writer` | subscription | Opus 5.5 | the spec text from the meanings |
| `routine` | subscription | Fable 5.2 in a subscription session | judgment that binds nothing |
| `worker` | subscription | Opus 5.5 | scouts, stages 0, 1, 5 to 10 by default |
| `specialist-code` | subscription | the host's code specialist agent | code work in stages 5 to 9 |
| `specialist-math` | subscription | the host's mathematics specialist agent | mathematics in stages 5 to 9 |
| `validator` | api | GLM, Kimi, Grok, Gemini, Astra (one call each) | `research validate` (its `model`) and the consilium panel (seats in `consilium.json`) |

### Flow of an M or L spec

1. Analysis: the session assembles the brief, the documents and the classed
   ledger into a prompt; `llm_call.py ask --role thinker --purpose analysis`
   writes `<spec>.meanings.md`; the answer must pass the meanings shape (C2).
2. Definition: a `writer` subagent writes the spec from the meanings, with the
   header of C3 and one Decisions row per `D<n>`. A gap goes back as
   `--purpose revision --reason writer-gap`; the writer never fills it (D5).
3. Research planning and research: scouts on `worker`, unchanged source rules.
4. Recommendation: one `thinker` call; Resolution: one `thinker` call only on a
   `disagree` (no merge step).
5. Verification: `research validate` (one `validator` call), then
   `consilium.py review --doc <spec> --doc <spec>.meanings.md`; the panel prompt
   names the meanings as the source the spec may not change, so a changed
   meaning comes back as a finding. The judge rules
   with `layer` on every accepted finding; `meaning` findings go to the thinker
   as `revision --reason meaning-finding`, `text` findings to the writer (D7).
6. Stage 4: for L, one `thinker` call for plan decisions; `plan_audit.py
   --models` checks the stage map (D27).
7. When the thinker's key is missing, `llm_call.py` exits 4 and names the
   limitation; the session takes the `thinker` role itself only if it runs the
   thinker's model on a subscription and records that in the brief, otherwise
   the M or L spec stops at definition and asks the owner (D24).

### Components

- `scripts/llm_call.py`: role resolution, the HTTP call, the retry rule, the cost
  rule, the ledger append, the thinker-purpose rules, the meanings shape check.
  Imported by `consilium.py` and `spec_protocol.py`; also a CLI (`ask`).
- `scripts/spend_ledger.py`: reads the monthly files, the Observatory command and
  the ceiling; writes `summary.md`; imported by `consilium.py` for the state line.
- `consilium.py`, `spec_protocol.py`, `plan_audit.py`: edited as C3 and C6 to C9 say.
- `assets/roles.example.json`, `assets/consilium.example.json`: templates.
- Tests: `test/llm_call_test.py`, `test/spend_ledger_test.py` (new, both in the
  `npm test` chain); `test/consilium_test.py`, `test/spec_protocol_test.py` and a
  `plan_audit.py --models` case extended.

## Contracts

### C1. Role map

Resolution order: `$TASK_PIPELINE_ROLES`, then `~/.config/task-pipeline/roles.json`,
then `assets/roles.example.json`. A `$TASK_PIPELINE_ROLES` naming a missing file
exits 2. A model starting with `<` is a placeholder and is never called (exit 2).

```json
{
  "schema": "task-pipeline-roles/1",
  "ceiling_usd": 5000,
  "observatory_spend_cmd": ["python3", "<path to Observatory>/tools/spend.py", "project", "--json"],
  "roles": {
    "thinker": {"model": "<the strongest model of the host's map>", "route": "api",
                "endpoint": "https://openrouter.ai/api/v1", "key_env": "OPENROUTER_API_KEY"},
    "writer": {"model": "<the subscription's top writing model>", "route": "subscription"},
    "routine": {"model": "<the thinker's model in a subscription session>", "route": "subscription"},
    "worker": {"model": "<the subscription's main model>", "route": "subscription"},
    "specialist-code": {"model": "<the code specialist>", "route": "subscription"},
    "specialist-math": {"model": "<the mathematics specialist>", "route": "subscription"},
    "validator": {"model": "<the default research validator>", "route": "api",
                  "endpoint": "https://openrouter.ai/api/v1", "key_env": "OPENROUTER_API_KEY"}
  }
}
```

`price` is optional, `{"in": X, "out": Y}` in USD per million tokens, both above
0 (a zero would book paid calls as free; refused, exit 2). `route` is `api` or
`subscription`; an `api` role without `endpoint` or `key_env` is refused (exit 2).
An `observatory_spend_cmd` element starting with `<` is a placeholder: the estate
figure is null.

### C2. Meanings file

`<spec>.meanings.md`. Level-2 headings exactly these seven, in this order: `Goal
and meaning`, `Key features`, `Decisions`, `Contracts`, `Non-goals`, `Risks`,
`Questions for the owner`. In Decisions, each decision is a line matching
`^\s*[-*]?\s*\**D(\d+)\b`; ids are unique. Other headings at level 2 fail.

### C3. Spec header for M and L

```
Size: M
```

`spec_protocol.py check` fails when: the header is absent (M, L); the path names
no file; the file's sha256 differs from the header's; the meanings fail C2; the
set of ids in the spec's `## Decisions` first column differs from the meanings'
set (both differences printed). In-flight specs: Q19.

### C4. `llm_call.py`

Python: `call(role, messages, *, task, script, stage=None, round=None,
model=None, endpoint=None, key_env=None, price=None, max_tokens=None, extra=None,
timeout=180)` returns `{text, finish, tokens_in, tokens_out, cost_usd,
cost_source, served_by, call_id, seconds, error}`; the keyword overrides let a
consilium seat name its own model.

CLI:

```
llm_call.py ask --role thinker --purpose analysis|recommendation|resolution|plan|revision
            --task T [--stage N] --prompt FILE --out FILE
            [--reason brief-changed|meaning-finding|writer-gap] [--evidence FILE]
            [--dossier DIR] [--spec FILE]
```

A purpose is refused (exit 2, nothing sent) when its result already exists, so a
call is never repeated on unchanged input, while a failed answer can be redone:

| Purpose | Refused when |
|---|---|
| `analysis` | `--out` already holds a file that passes C2 (a change goes through `revision`) |
| `recommendation` | `--dossier` is missing, or its `## Recommendation` already has text |
| `resolution` | `--dossier` is missing, its `## Validation` table holds no `disagree`, or its `## Resolution` already has text |
| `plan` | `--spec` is not `Size: L`, or `--out` already exists and is not empty |
| `revision` | `--reason` or `--evidence` (the changed brief, the `judge.json`, or the writer's gap note) is missing |

For `analysis` and `revision` the answer written to `--out` must pass C2,
otherwise exit 1 (the row is booked).

Retry: one retry only when the first attempt returned no `usage`; an answer with
usage is never retried, parsed or not (D9, for every caller, Q8).

Exit codes: 0 answer written; 1 the call failed or the answer failed its shape;
2 usage, no task id, placeholder, subscription role, or a purpose refused; 3 the
ledger write failed (result kept, row on stderr; 3 wins over 1); 4 the role's key
variable is empty. `consilium.py` and `spec_protocol.py` keep their documented
exit 2 for a missing key and adopt exit 3.

### C5. Ledger row

File `$TASK_PIPELINE_SPEND_DIR` or `~/.local/state/task-pipeline/spend/`,
`YYYY-MM.jsonl` by the row's UTC `ts`, one JSON object per line, appended with
one `os.write` on a descriptor opened `O_APPEND`, under an in-process lock.

| Field | Value |
|---|---|
| `ts` | UTC, `YYYY-MM-DDTHH:MM:SSZ`, when the response arrived |
| `call_id` | `uuid4` hex |
| `script` | `<script>:<purpose>`: `llm_call.py:analysis` (and the other purposes, `revision/<reason>` for revisions), `consilium.py:panel`, `consilium.py:judge`, `spec_protocol.py:validate` |
| `role` | `thinker` or `validator` |
| `route` | `openrouter`; `openrouter-byok` when the endpoint is OpenRouter and the cost rule took the `upstream` branch; `direct-api` for any other endpoint |
| `model` | the response's `model` field |
| `task` | `--task` or `$TASK_PIPELINE_TASK` |
| `repo` | basename of `git rev-parse --show-toplevel`, null outside a repository |
| `stage` | `--stage` or `$TASK_PIPELINE_STAGE` as an integer, else null |
| `round` | the round directory relative to `repo` for consilium rows, else null |
| `tokens_in`, `tokens_out` | `usage.prompt_tokens`, `usage.completion_tokens` |
| `cost_usd` | by D15, rounded to 6 decimals, or null |
| `cost_source` | `upstream`, `provider`, `price-table`, `unpriced` |
| `raw_cost`, `raw_upstream_cost` | c and u as returned, null when absent |

Example, the analysis call that produced this spec's meanings (values from its
metadata; provider branch: c > 0, u absent):

```json
{"ts": "2026-11-23T19:28:16Z", "call_id": "9b2f6c0e4d7a4f1e8c3b5a6d7e8f9a0b", "script": "llm_call.py:analysis",
 "role": "thinker", "route": "openrouter", "model": "anthropic/claude-fable-5.2", "task": "model-budget-ab",
 "repo": "task-pipeline", "stage": 2, "round": null,
 "tokens_in": 6607, "tokens_out": 12438, "cost_usd": 0.550376, "cost_source": "provider",
 "raw_cost": 0.550376, "raw_upstream_cost": null}
```

### C6. Round ledger, `consilium-ledger/2`

`round-N/ledger.json`: `{schema, round, kind, config, cap_usd, calls, panel_usd,
judge_usd, spent_usd, warnings, started, finished}`. `calls` holds one entry per
booked row: the C5 row plus `id`, `family`, `parsed`, `seconds`, `error`. Entries
are only appended; the file is rewritten through a temporary file and a rename.
`panel_usd` sums rows whose `id` is not `judge`, `judge_usd` the rest, `spent_usd`
both; a null cost counts 0 in these sums. An attempt with no usage has no
row; its error stays in `<seat>.json`. Each judge run writes `judge.json`; a
previous one is kept as `judge.<call_id>.json`.

### C7. Ruling

Each `accepted` item gains `"layer": "meaning" | "text"`. `meaning` means the
finding changes a decision, a contract or a key feature; `text` means it changes
only the wording or completeness of the spec.

### C8. Consilium configuration

`consilium.json` holds `schema`, `min_panel` (3), `max_usd_per_round` and
`panel`: exactly five seats with families `glm`, `kimi`, `grok`, `gemini`,
`astra`, each `{id, model, family, max_tokens, lens, endpoint?, key_env?,
price?}`; a seat without `endpoint` or `key_env` uses the `validator` role's. A
`judge` key, a sixth seat, another family, or a seat whose model shares the vendor
prefix (the text before `/`) of the `thinker` or `writer` model (the Fable and
Opus families) is refused (exit 2). The judge is `roles.thinker`. The judge runs
whenever three or more verdicts came back, whatever the spend; over the cap it
adds `judge over the round cap by USD x` to `warnings`, and a null-cost judge row
adds `judge unpriced`. `--judge-only` is refused (exit 2, nothing sent) when the
round already holds a parsable ruling: one verdict is bought per round.

`check` passes only with: at most one row per seat with tokens above zero; at
least three verdicts of three families; `panel_usd` at most `cap_usd` and no
null-cost panel row (the cap cannot be proven without it); a parsable ruling with
`layer` on every accepted finding; `judge.json` `meta.model` equal to
`roles.thinker.model`; the C6 prefix rule; and R8's equality. It prints the
round's `warnings`.

### C9. `plan_audit.py --models`

A value is `default`, `inherit`, one of the seven role names, or a literal model
id containing `/`. A role name must resolve to a non-placeholder model in the
role map; any other bare word fails as an unknown role.
`pipeline.schema.json`'s `model` description lists the role names.

### C10. `spend_ledger.py`

```
spend_ledger.py summary --day YYYY-MM-DD [--json]
spend_ledger.py summary --month YYYY-MM [--json]
spend_ledger.py check [--month YYYY-MM]      (default: the current UTC month)
```

`summary --json`:

```json
{"schema": "spend-summary/1", "period": "2026-11", "rows": 57, "malformed": 0, "unpriced": 0,
 "total_usd": 312.4, "by_route": {"openrouter": 312.4},
 "by_model": {"anthropic/claude-fable-5.2": 250.0, "moonshotai/kimi-k3.1-pro": 40.0, "z-ai/glm-5.3": 22.4},
 "by_role": {"thinker": 250.0, "validator": 62.4}, "by_task": {"model-budget-ab": 312.4},
 "estate": {"as_of": "2026-11-10", "total_usd": 2000.0, "ceiling_usd": 5000, "projected_usd": 6000.0, "state": "warn"},
 "mismatch": false, "state_line": "Spend 2026-11: estate USD 2000.00 of 5000.00 (warn), projected USD 6000.00; this host's ledger USD 312.40, 0 unpriced."}
```

`total_usd` sums non-null costs; each `by_*` map sums to it. `--day` filters rows
by date; `estate` is always the current UTC month as of today, whatever period
is asked. The text output's first line is
`state_line`; every `summary` run rewrites `<spend dir>/summary.md` with the text
output. `check` exits 1 on a line that is not a JSON object with the D14 key set,
or a null `cost_usd`, naming file and line; 0 otherwise.

Estate figure: run `observatory_spend_cmd` (argv, 30 s timeout); an object with a
numeric `totalUsd` gives it; a list of such objects gives their sum; anything
else gives null.

State, with C the ceiling, E the estate figure, d the UTC day of month and n the
days in the month: null E is `unknown`; E at least C is `over`; at least 0.95 C
is `critical`; at least 0.8 C, or E / d * n at least C, is `warn`; else `ok`.

State line: `Spend <YYYY-MM>: estate USD <E or unknown> of <C> (<state>),
projected USD <p or unknown>; this host's ledger USD <total>, <k> unpriced.`
with `; accounting mismatch` before the full stop when the ledger total exceeds
E. Amounts use two decimals and no thousands separator.

## Edge cases

- No task id: exit 2 before any request; the ledger is unchanged (D16).
- Thinker key empty: exit 4, the D24 fallback (Flow step 7).
- Spend dir unwritable or full: the answer is kept, the row goes to stderr as
  one JSON line, exit 3 (D17).
- First attempt drops the connection (no usage): one retry; a second failure is
  a missing verdict and leaves no row.
- An answer with usage that does not parse: booked, not retried, a missing
  verdict (D9).
- BYOK: c = 0 with the real cost in u gives `upstream`, route `openrouter-byok`.
- No cost and no price: `unpriced`; `spend_ledger.py check` exits 1; a panel row
  fails the round, a judge row is a round warning; the fix is a `price` on the
  role or seat.
- Panel spend over the cap: the judge still runs (D11); `check` fails the round.
- Fewer than three verdicts: the judge is skipped and the round fails, as today;
  the reason is the verdict count, never money (Q10).
- A `consilium-ledger/1` round (before the change): `check` applies the
  v1.113.0 rules and prints that; `--judge-only` keeps its calls as they are and
  R8's equality is not computed for it (no backfill).
- Two councils of one task (stage 3 review, L plan): rows differ by `round`
  directory, so R8 counts per council (Q4).
- A truncated ledger line: `summary` skips and counts it in `malformed`;
  `check` exits 1 naming the line.
- Observatory missing, failing, slow or returning another shape: `unknown`,
  never `ok` (D21).
- Early in a month the projection is volatile (USD 200 on day 1 projects 6,000
  in a 30-day month): `warn`, which blocks nothing (D23).
- Several hosts: each has a partial ledger; only Observatory is estate truth,
  and the mismatch check compares this host's part against it.
- The served model differs from the requested one: the row records the served
  `model`; the judge check compares the requested id.
- An S spec that names a meanings file is checked by C3 all the same.

| D28 | Replay: two finished M specs are rebuilt from their briefs through the split; `consilium.py decide` compares old and new blind; the split passes if the new spec wins or ties both times. | "Do not lose quality" needs a comparison, not a claim. |
| D29 | The rule takes effect on merge; the ledger starts on 2026-11-23 with no backfill; a quality review is due on 2026-12-07. | Fourteen days gives the first specs under the split. |

## Rollout

1. Build on a branch; one PR (a public contract changes). Version: the next
   minor after v1.113.0, read from the remote tags at release; the five version
   surfaces and the CHANGELOG move together.
2. During the build, run `observatory_spend_cmd` once on this host and record its
   real output shape in the PR body and in `assets/roles.example.json`'s note
   (D20).
3. Host setup in the same change: write `~/.config/task-pipeline/roles.json`
   from the host's model map, rewrite the host `consilium.json` to the five
   seats (the old six-seat file is refused), run `spend_ledger.py summary
   --month 2026-11` and record the printed state in the PR; `unknown` means the
   command is reworked under Risks, and the line stays loud meanwhile.
4. Board row to Observatory (D22), body: "task-pipeline writes every token call
   to `~/.local/state/task-pipeline/spend/YYYY-MM.jsonl` and prints a
   `spend-summary/1` JSON with `spend_ledger.py summary --month YYYY-MM --json`
   (fields in task-pipeline's spec, C10). Please render it beside the estate
   total, with the state against the USD 5,000 ceiling. No change to
   Observatory's code is asked beyond reading this output."
5. Merge makes the rule effective; the ledger starts 2026-11-23 with no backfill
   (D29).
6. Replay (D28) after merge, recorded under `docs/research/<date>-split-replay/`.
7. Board row due 2026-12-07: the quality review. It measures the three
   refutation tests under Risks and records, with the evidence, whether the
   split stands or is refuted.

## Risks

- OpenRouter may report u on ordinary calls with c below u; D15 would then
  double count. The reconciliation exposes it; the raw fields allow a recount.
- The shape of Observatory's output is not verified. If `totalUsd` covers one
  project per call, the configured command must iterate; until it works the
  state is `unknown`, which is loud.
- Observatory's month boundary may differ from UTC, shifting totals at month
  edges.
- The ledger is per host; only Observatory is estate truth.
- Dropping the sixth seat removes one family; five remain against a floor of
  three.
- The writer may soften a meaning without changing a decision id; only the panel
  catches that.
- Refuted if: either replay loses; the round-1 pass rate of the first three split
  specs is below that of earlier specs; or the judge accepts more than one
  "writer changed a meaning" finding by 2026-12-07.
