## Goal

Every stage of task-pipeline runs on a named role that the host's `roles.json` resolves to one model on
one route. Tokens pay only for the thinker (Fable 5.2 by API) and the five validators; the writer, routine
judgment, the workers and the specialists run on subscriptions. Every token call writes one ledger
row through one module, and the owner sees this host's day and month spend and the estate's month total
against the USD 5,000 ceiling, with a warning before it is reached. This replaces the rule of 2026-11-22
("the spec's author is the session's own model"). Quality is held by the thinker deciding every meaning,
the blind panel, and a replay that gates the merge.

Done when R1 to R12 pass their acceptance checks, the replay of Rollout step 6 passes, and
`npm test` (including `python3 test/prompt_lint.py`) is green on the merge commit.

### Flow of one spec

1. Preflight: `llm_call.py preflight --role thinker` (stop with the missing key named, D24), then the
   state line (R7).
2. `spec_protocol.py meanings write` (thinker, `analysis`) writes `<spec>.meanings.md`;
   `spec_protocol.py check` reads its shape (C11).
3. The writer, a subagent pinned to `roles.writer.model`, writes the spec from the meanings and the brief;
   a gap it cannot settle as a tactic goes back as a `revision` call (D5), never filled.
4. Research (M and L): scouts as `worker`; Recommendation and Resolution as thinker calls; `research
   validate` as R9.
5. `consilium.py review`: five validators, judge `thinker` (`verdict`); accepted findings routed by
   `layer` (D7).
6. `spec_protocol.py check` and `gate`; `consilium.py check`.

### `llm_call` internals

`call(role, messages, *, task, purpose=None, stage=None, round=None, seat=None, run=None, max_tokens,
timeout) -> Result`. It resolves the role (R1), refuses as R3 and R10, builds an OpenAI-compatible
`chat/completions` request to the entry's endpoint with the key read from `key_env` (never logged),
sends it once, and writes the row (C3) whatever happened: `status` is `ok` on a 2xx response with a
body, `http-error` on any other status, `timeout`, or `transport-error`. Usage is read from
`usage.prompt_tokens`, `usage.completion_tokens`, `usage.cost` and
`usage.cost_details.upstream_inference_cost`; the request asks OpenRouter for usage accounting. The
`model` field is the response's `model`, else the requested id. The route is derived as D14 states from
the endpoint's host and the entry's `byok` (default false).

### Ceiling

```
state(figure, date):
  if figure is None:            unknown
  elif figure >= 5000:          over
  elif figure >= 4750:          critical
  elif figure >= 4000:          warn
  else:
    d = max(1, date.day)        # UTC
    if d >= 3 and figure / d * days_in_month(date) >= 5000: warn
    else:                       ok
```

### C2. `llm_call.py`

| Verb | Arguments | Exit |
|---|---|---|
| `call` | `--role R --task T [--purpose P] [--stage N] [--round N] --prompt FILE --out FILE [--max-tokens N] [--timeout S]` | 0 `ok`; 1 a row with another status; 2 refused, no request, no row; 3 ledger write failed (row in `uncommitted.jsonl`) |
| `preflight` | `--role R [--role R ...]`, `validators` meaning all five | 0 ready; 2 the first missing `endpoint` or `key_env` named |
| `resolve` | `[--json]` | 0 and the map with its source, no key values; 2 as R1 |

The task id is `--task`, else `$TASK_PIPELINE_TASK`. The spend dir is `$TASK_PIPELINE_SPEND_DIR`, else
`~/.local/state/task-pipeline/spend/`.

### C3. Ledger row (one JSON object per line)

```json
{"ts": "2026-11-23T19:48:01Z", "call_id": "7f3a9c1e04b2.Astra.1", "script": "consilium.py", "role": "validators.Astra", "route": "openrouter-byok", "model": "openai/gpt-6.2-astra-pro", "task": "model-budget-ab", "repo": "task-pipeline", "stage": "3", "round": 1, "status": "ok", "tokens_in": 18979, "tokens_out": 3719, "cost_usd": 0.25731, "cost_source": "upstream", "raw_cost": 0, "raw_upstream_cost": 0.25731}
```

The D14 fields plus `status` (D17): `ok`, `http-error`, `timeout`, `transport-error`. `call_id` is
`<run>.<seat>.<n>`: `run` is the first 12 hex digits of the sha256 of the round directory's absolute
path for consilium calls, else 12 random hex digits per process; `seat` is the validator key, `judge`,
or the purpose; `n` counts attempts of that seat in that run from 1. `repo` is the basename of the git
top level, else null; `stage` and `round` are null outside a stage or round. A row without usage has
`tokens_in`, `tokens_out`, `raw_cost`, `raw_upstream_cost` and `cost_usd` null and `cost_source:
unknown`. `uncommitted.jsonl` holds rows of this shape only.

### C4. Cost rule (D15), with c = `raw_cost`, u = `raw_upstream_cost`

A value that is not a number, or is negative, counts as absent; `cost_usd` is rounded to 6 decimals.

| c | u | price | `cost_usd` | `cost_source` |
|---|---|---|---|---|
| no usage | | | null | `unknown` |
| 0 or absent | above 0 | any | u | `upstream` |
| above 0 | any | any | c | `provider` |
| 0 | 0 | any | 0 | `provider` |
| other (for example both absent) | | present | tokens_in/1e6 x in + tokens_out/1e6 x out | `price-table` |
| other | | absent | null | `unpriced` (a defect: `check` fails) |

### C5. Round `ledger.json` (schema `consilium-ledger/2`)

```json
{"schema": "consilium-ledger/2", "round": 1, "kind": "review", "task": "model-budget-ab", "run": "7f3a9c1e04b2",
 "started": "2026-11-23T19:47:10Z", "cap_usd": 10.0, "cap_warning": false,
 "rows": [{"call_id": "7f3a9c1e04b2.Astra.1", "seat": "Astra", "family": "openai", "parsed": true, "status": "ok", "cost_usd": 0.25731, "cost_source": "upstream"}],
 "spent_usd": 0.25731, "unknown_cost_rows": 0, "quorum": "pending"}
```

`rows` only grows. `spent_usd` is the sum of `rows[].cost_usd` (null counts 0); `quorum` is `pending`
until the round is checked, then `valid` or `insufficient`. The example shows one row of a round in progress.

### C6. Ruling additions (`judge.json`, `ruling.accepted[]`)

Every accepted finding carries `"layer": "meaning" | "text"`; one that says the writer changed a meaning
also carries `"fidelity": true`. `decide` rulings inside a replay carry `"pick": "A" | "B" | "tie"`.

### C7. `consilium.py check DIR --round N`

Fails (exit 1) on: a validator key with zero or more than one attempt row by `call_id`; fewer than five
validator rows; a ruling that does not parse, or an accepted finding without `layer`; the judge's
requested model in `judge.json` differing from `roles.thinker.model`; an accepted finding with
`fidelity: true` in the latest round (it blocks release). With five rows present it counts parsable
verdicts and their families: under three of three families the round is written `quorum: insufficient`
and the check fails; otherwise `quorum: valid`. A cap overrun prints a warning and does not fail. The
completeness check (C3's `call_id` set of the round's `ledger.json` equal to the global rows whose
`call_id` starts with `<run>.`, read from the month files spanning `started` to the last row, with equal
`cost_usd` sums within 1e-6) runs in the same verb.

### C9. Observatory output (D1, D20)

`observatory_spend_cmd` must print one JSON value: an object with numeric `totalUsd`, or a list of such
objects. Any other value, invalid JSON, a non-zero exit or the 60-second limit gives `unknown`; only a
wrong shape also fails `spend_ledger.py check`. The figure counts as the estate total only when the
output covers Observatory's inventory: every list item (or the single object) carries a `project` id,
no id repeats, and the set of ids equals the list printed by `observatory_inventory_cmd`; then the
figure is the sum of `totalUsd`. Missing inventory, a missing or extra id, or a repeat gives `unknown`.

### C11. Meanings file and spec header (D3, D4)

The meanings file is `<spec>.meanings.md`: optional header lines, then exactly the level-2 sections Goal
and meaning, Key features, Decisions, Contracts, Non-goals, Risks, Questions for the owner, in that
order. Its D lines are the lines of `## Decisions` matching `^- D[0-9]+: `. The spec's header carries
`Meanings: <path> sha256:<64 hex>`, the path relative to the spec or absolute. `spec_protocol.py check`
passes only when: the file exists; its sha256 equals the header's; its sections are those seven in order;
and the set of D lines in the spec's `## Decisions` (same pattern; table rows do not match) equals the
meanings' set, compared as exact byte strings.

```json
   "seed": "9b74c4b3c9fddbf5b2f3a41b502acb275f8712e2c393317ddaa938687f681cf7", "order": {"A": "old", "B": "new"}, "pick": "tie", "result": "tie", "decide_dir": "s2-design-tester-config/replay"}],

```

Paths are relative to `docs/research/2026-11-23-model-budget-ab/`. Labels are stripped by removing every
header line before the first `## ` heading and any line naming a file of the pair; the order is `new`
first when the first hex digit of `seed` is even. `result` is `order[pick]`, or `tie`. `pass` is true
only for two pairs whose results are `new` or `tie`. The example's seeds are illustrative values that
follow the order rule (4 is even, so `new` is A; 9 is odd, so `old` is A); the real seed is the sha256 of
the old file's bytes followed by the new file's.

## Edge cases

- The ledger append races another process: each row is one `os.write` under `O_APPEND`, so lines do not
  interleave; a row over 4,096 bytes is not expected (no free text in rows).
- A round spans a month boundary: C7 reads both month files.
- The thinker's key is missing at preflight: no model is called, no row is written, exit 2 (D24); the
  routine subscription Fable never stands in.
- Observatory is slow or down: `unknown`, the state line says so, calls go on (D23).
- `roles.json` changes between a round and its check: C7 fails on the judge model; the round is rerun,
  since its verdict came from a model that is no longer the thinker.
- A validator answers with usage but unparsable JSON: one row with its cost, `parsed: false` in the round
  ledger, a missing verdict (D9); no second request.
- The response lacks `model`: the requested id is recorded.
- c = 0 with u absent, or c absent with u = 0: price-table (C4), since the rule assigns `provider` only
  to c above 0 or c = u = 0.
- A dossier of size L validated only with Kimi: `research check` keeps today's rule of two families and
  fails until the Gemini run exists.
- The baseline cohort of the 2026-12-07 review is empty: the pass-rate comparison is recorded as "no
  baseline" and the other two refutation conditions still decide.
- A size-S spec with no research: it still owes `Meanings:` (D2); its research rules are unchanged.
- `--judge-only` after a full round: allowed; it appends judge rows with `n` incremented.
- Observatory's month may not end at UTC midnight: the state line and `summary.json` name UTC dates, and
  a reconciliation `accounting mismatch` in the first or last day of a month is read with that in mind.
- Several hosts: each keeps its own ledger and labels its totals "this host"; only the Observatory
  figure is the estate.

## Decisions

The meanings' decisions, verbatim (C11 compares these lines byte for byte):

- D1: The role map is `~/.config/task-pipeline/roles.json`, overridden by `$TASK_PIPELINE_ROLES`, template `assets/roles.example.json`, whose placeholders scripts refuse. Each role has `model` and `route` (`api` or `subscription`); an `api` role also `endpoint`, `key_env` and a `price` (USD per million tokens in and out) that resolution requires. `validators` maps exactly GLM, Kimi, Grok, Gemini and Astra, each to `model`, `endpoint`, `key_env` and `price`; `research validate` uses Kimi, plus Gemini for L. Top-level `observatory_spend_cmd` holds D20's command; output other than an object with `totalUsd` or a list of such gives `unknown` and fails `check`. Because the existing rule forbids hardcoded ids and consilium configuration already uses this pattern.
- D2: The split applies to every size and every path that writes a spec. Because the order names no size and replaces the 2026-11-22 rule.
- D3: The meanings file is `<spec>.meanings.md` with seven sections in order: Goal and meaning, Key features, Decisions, Contracts, Non-goals, Risks, Questions for the owner; decisions are lines `D<n>`. Because a fixed shape lets a script check the writer's fidelity.
- D4: The spec header carries `Meanings: <path> sha256:<hex>`. Because the gate must prove which meanings the text was written from.
- D5: The writer returns a gap in the meanings to `thinker` as a revision call and never fills it itself. Because the writer may not invent a decision.
- D6: `thinker` makes only these calls: analysis with meanings, research Recommendation and plan decisions at any size (one each), every Resolution, the consilium verdict (one per round), the replay verdict, binding decisions arising in stages 5 to 9, and a revision when the brief changed, the judge accepted a meaning-layer finding or the writer reports a gap in the meanings. None repeats on unchanged input. Because "without stinting" means no cap on needed calls, not calls on unchanged input.
- D7: `judge.json` marks every accepted finding `layer: meaning|text`; meaning findings go to `thinker`, text ones to the writer. Because routing by layer keeps token calls to decisions.
- D8: The panel is exactly the five named validators, chosen by key, not seat; the sixth seat is dropped. Families: GLM Zhipu, Kimi Moonshot, Grok xAI, Gemini Google, Astra OpenAI (the measured BYOK seat); none is Anthropic, the thinker's and writer's family, so Fable and Opus never sit. A round is valid with three parsable verdicts of three families, the existing `consilium.py check` rule. Because the owner named the five, and both author families are now the author.
- D9: One request per validator per round, never retried for any cause: timeout, transport failure, missing usage or an unparsable answer is a missing verdict. Because the order says one request each.
- D10: The judge comes from the `thinker` role, not `consilium.json`. Because one source prevents drift.
- D11: `max_usd_per_round` is advisory: an overrun records a warning and never skips a validator or the judge. Because the order names the five who answer and makes Fable's verdict unconditional.
- D12: Only the new standard-library module `scripts/llm_call.py` connects to a model; `consilium.py` and `spec_protocol.py` call it. Because only one path guarantees every call is recorded.
- D13: The ledger is `~/.local/state/task-pipeline/spend/YYYY-MM.jsonl` (directory overridable by `$TASK_PIPELINE_SPEND_DIR`), one line per call in a single append, UTC timestamps. Because monthly files make the month summary one read.
- D14: Row fields are `ts`, `call_id`, `script`, `role`, `route` (`openrouter`, `openrouter-byok`, `direct-api`), `model` (as returned), `task`, `repo`, `stage`, `round`, `tokens_in`, `tokens_out`, `cost_usd`, `cost_source`, `raw_cost`, `raw_upstream_cost`. Route: openrouter.ai with the config's `byok` flag is `openrouter-byok`, without it `openrouter`, any other host `direct-api`. Because the order names route, model, cost and task, and the raw fields allow a later recount.
- D15: Cost rule (c = `usage.cost`, u = `usage.cost_details.upstream_inference_cost`): c 0 or absent with u > 0 gives u, `upstream`; c > 0 gives c, `provider`, never adding u; c = u = 0 gives 0, `provider`; else a `price` gives the token-computed figure, `price-table`; else null, `unpriced`. Both raw fields are kept. Because the measured BYOK case reports c = 0 with the real cost in u, and blind summing would double count ordinary calls.
- D16: A token call without a task id (`--task` or `$TASK_PIPELINE_TASK`) exits 2 before any request. Because an unattributed row cannot be repaired after the money is spent.
- D17: Every dispatched attempt writes a row with a `status`; without usage, `cost_usd` is null and `cost_source` `unknown`. On a failed ledger write the result is kept, the row goes to `uncommitted.jsonl` in the spend dir and the script exits 3; `spend_ledger.py check` exits 1 while that file has a line. Because billed failures are spend, and a lost row must be loud.
- D18: A round's `ledger.json` becomes append-only: `--judge-only` appends judge rows, panel rows stay; the round total sums all rows. Because the measured rerun zeroed the panel's cost.
- D19: New `scripts/spend_ledger.py`: `summary --day YYYY-MM-DD | --month YYYY-MM [--json]` and `check`, which exits 1 on a malformed or unpriced row. Because the owner needs a view, and unpriced spend must not hide.
- D20: The estate month total is Observatory's, through `observatory_spend_cmd` (default `tools/spend.py project --json`), reading `totalUsd`, summed over a list; it counts only when it covers every project in Observatory's inventory once, else `unknown`. The build runs it once and records its real shape. Because Observatory measures at the providers across all projects; the ledger sees one host.
- D21: Ceiling states on the estate total: `ok` only below USD 4,000 with the projection below 5,000; `warn` from 4,000, or when the projection (month-to-date over elapsed days, times days in the month) reaches 5,000; `critical` from 4,750; `over` from 5,000; `unknown` with no Observatory figure. Elapsed days is the UTC day of month, minimum 1; projection applies from day 3; higher states beat a projected `warn`. Because a warning must come while there is room to act.
- D22: The state line prints in every run's preflight notice, each round's `summary.md` and the final report; the summary also goes to the spend dir. The Observatory view is a deliverable, accepted when day and month totals read there; the build first checks whether Observatory renders an external JSON row unchanged, else names the one Observatory change. Because Observatory is the owner's surface and OpenRouter's view understates BYOK cost.
- D23: The ceiling warns and never blocks a call. Because the order asks for a warning, and blocking would stint the thinking it protects.
- D24: Without the thinker's API endpoint or key, preflight stops before definition and any panel dispatch, naming the missing key and calling no model; likewise for the judge. Subscription Fable is `routine` only. Because the order puts key thinking on Fable through the API; any swap is a silent downgrade.
- D25: Subscription calls are not ledgered. Because they have no marginal cost and the order tracks token routes.
- D26: In `model-tiering.md`, "Roles and routes" replaces the sections on the spec's author and the plan-then-execute profile, mapping its provisions: stages 0 to 4 to `thinker`, `writer` and `routine`; 5 to 9 to `worker` and the specialists; 10 to `routine`, its consilium verdict to `thinker`; the operator's override to `roles.json`; size-independence to D2; a one-tier host maps every subscription role to that tier. "Subagents" pins each subagent to its role's model; `spec-protocol.md`'s loop table and research roles and `consilium.md`'s money paragraph are edited in place; Markdown words do not grow. Because the ratchet forbids growth and the role map supersedes both sections.
- D27: Stage configs and `plan_audit.py --models` accept role names alongside `default` and `inherit`. Because the recorded map must stay checkable at stage 4.
- D28: Replay test: two finished M specs rebuilt from their briefs through the split; `consilium.py decide` compares old and new blind; the split passes if the new spec wins or ties both times. Because "do not lose quality" needs a comparison, not a claim.
- D29: Merge, gated by the Replay contract, activates the rule; the ledger starts then, without backfill. A quality review due 2026-12-07, a backlog row run in the stage-10 retrospective, compares round-1 pass rates (verdict `pass` over parsable round-1 rulings) of the first three split specs and the last five earlier M or L specs with a consilium ruling (or fewer). On refutation the thinker revises the split; the session-author rule returns only on the owner's word. Because fourteen days gives the first specs under the split.
