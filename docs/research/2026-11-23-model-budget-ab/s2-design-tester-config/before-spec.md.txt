# Spec: device configurations in the design-tester's panel walk

Size: M
Author: anthropic/thinker
Repository: task-pipeline
Source: board request 77741b8d (test-stand-agent, 2026-11-23)

## Goal

Configuration-dependent bugs (right-to-left, largest text, small screen, tablet, long words, dark theme) are visible only in that configuration. Each panel persona gets one fixed device configuration, and the design-tester judges every step in it. The `design-review/1` report names the configuration per row and marks findings that exist only there, and `design_gate.py` checks all of it. For mobile nodes, the build pass may reuse screenshots from a finished test-stand run instead of capturing them itself.

## Scope

In:
- `scripts/design_gate.py`: the `panel` and `report` verbs.
- `agents/design-tester.md`: inputs, procedure, report shape.
- `references/design-review.md` (the doctrine file the agent cites): panel section, passes table, degradation.
- Tests for the gate; one backlog row; the reply on board request 77741b8d.

Out:
- `agent-tester`: no change. It judges agent surfaces, not device screens.
- The super-ux panel template. A board request to super-ux is filed (Rollout); until it lands, projects add the line by hand.
- Any change to the test stand. This spec defines only what task-pipeline consumes.
- A full cross product of personas and configurations. The matrix stays scenarios times personas.
- Starting, scheduling or waiting on stand runs. The tester only reads finished runs.
- Code from any other project. Everything is written here, stdlib only.

## Design

### One configuration per persona

A configuration has four axes: `device`, `locale`, `text`, `theme`. Direction is derived from the locale and never written, so the two cannot disagree. Each portrait holds exactly one configuration. Ten personas therefore give ten cells at no extra matrix cost. The hard cells are spread across the panel, and the panel gate checks that the spread exists.

The `needs` line stays prose about the person. `config` is the normative test configuration. The gate does not cross-check the two.

### Direction, derived

`dir(locale)` is `rtl` when:
- the locale is `pseudo-rtl`; or
- its second subtag is a four-letter script in {Arab, Hebr, Thaa, Syrc, Nkoo}; or
- it has no four-letter script subtag and its primary subtag is in {ar, he, fa, ur, ps, sd, yi, dv, ckb, ug}.

Otherwise it is `ltr`. An explicit other script wins: `sd-Deva` is ltr.

### What "applied" means

- Pass B: an axis is applied when the environment that produced the capture was set to the persona's value, default values included. If the app ignores the setting (no dark theme exists), the axis is still applied; whether that is a finding is the tester's judgment.
- Pass D: an axis is applied when the frame or mockup read was drawn at the persona's value. Most designs draw one variant, so gaps are normal there. The tester still judges `text_fit` and `controls` for the persona's configuration by reasoning, and says so in the finding's `what`.

An approximation counts as applied only if it appears in the table below, and the row names it in `config_how`.

### Realizing a value

This table is guidance for whoever captures (a stand cell or the tester). It goes into `references/design-review.md`. The gate checks none of it. Tool flags are to be confirmed against the installed versions (Q9).

| Value | iOS simulator | Android | Browser |
|---|---|---|---|
| `small-phone` (shorter side up to 375) | a model in class | a profile in class | viewport 360x640 |
| `large-phone` (shorter side 376 to 599) | a model in class | a profile in class | viewport 430x932 |
| `tablet` (shorter side 600 or more) | an iPad | a tablet profile | viewport 820x1180 |
| `desktop` | not applicable | not applicable | viewport 1440x900 |
| `pseudo-rtl` | launch args `-AppleTextDirection YES -NSForceRightToLeftWritingDirection YES` | locale `ar-XB`, pseudolocales enabled in the build | the project's RTL pseudo-locale, else `dir="rtl"` on the root element (approximation) |
| `pseudo-double` | launch arg `-NSDoubleLocalizedStrings YES` | locale `en-XA` (approximation: lengthened, not doubled) | the project's pseudo-locale, else a gap |
| `largest` | `xcrun simctl ui <device> content_size accessibility-extra-extra-extra-large` | `adb shell settings put system font_scale 2.0` | the driver's 200% text or minimum font size setting, else a gap |
| `dark` | `xcrun simctl ui <device> appearance dark` | `adb shell cmd uimode night yes` | the driver's `prefers-color-scheme: dark` emulation, else a gap |

### "Only in this configuration"

A finding is config-only when a control look at the same scenario step does not show it, and the control's configuration differs on the axes blamed. The cheapest control is another persona's row for the same step in the same pass. Failing that, the tester takes one extra capture or frame, at most one per finding. Without a control the finding is still reported; it just does not carry `config_only`.

### Stand intake (mobile nodes, pass B)

1. `pipeline.json` gains an optional `stand` block (C8). If it is absent, this path does not exist and the tester captures as today.
2. The tester asks the stand's door for a finished run of the node's build. The call runs under the project's secret runner with the client key in the environment, never on the command line or printed. It does not start a run and does not poll. No finished run for this build means self-capture.
3. It saves the door's raw response and the screenshots beside its own captures. It then writes a normalized manifest (C6) next to the report as `<report-stem>.stand-<run>.json`.
4. A stand capture serves a row only if the stand tagged it with that scenario and step and its cell's configuration equals the persona's on all four axes. Untagged `explore` screenshots serve no row.
5. The `outcome` check uses the outcome the stand recorded for that capture, if any. Otherwise the tester reads the outcome back itself or sets `outcome` to NOT_RUN with the reason `stand capture carries no outcome`.
6. Rows with no matching cell fall back to self-capture. If there is no local channel either, the row is NOT_RUN with that reason.

The exact door verbs are not known from the brief (Q5). The gate depends only on the local manifest, so it is buildable now. The agent's fetch step ships in phase 2 once the door contract is confirmed.

## Contracts

### C1. Panel `config` field

Written with the same field markup the parser already accepts for `needs`. The implementer reuses that extraction and does not add a second syntax. Value:

```
device=<small-phone|large-phone|tablet|desktop>; locale=<tag>; text=<default|largest>; theme=<light|dark>
```

- Four `key=value` pairs separated by `;`, in any order, each key exactly once, whitespace trimmed.
- `locale` is `pseudo-rtl`, `pseudo-double`, or matches `^[a-z]{2,3}(-[A-Za-z0-9]{2,8})*$`.
- Any violation is `CFG-PANEL-SYNTAX` (FAIL), naming the portrait and the key.

### C2. Hard cells and declines

| Cell | Satisfied by a portrait with |
|---|---|
| `rtl` | derived direction rtl |
| `double-length` | `locale=pseudo-double` |
| `largest-text` | `text=largest` |
| `dark` | `theme=dark` |
| `small-screen` | `device=small-phone` |
| `tablet` | `device=tablet` |

Decline line: anywhere in the panel file, after stripping a leading `- ` and whitespace, matching `^Config declined: (rtl|double-length|largest-text|dark|small-screen|tablet): (\S.*)$`. A line starting `Config declined:` that does not match is `CFG-PANEL-SYNTAX`.

### C3. Row additions (`design-review/1`, additive, schema string unchanged)

```json
{"config": {"device": "small-phone", "locale": "pseudo-rtl", "text": "default", "theme": "light"},
 "config_applied": ["device", "locale", "text", "theme"],
 "config_gap": "no dark variant of this frame",
 "config_how": "dir=rtl on the root element",
 "capture_source": "self",
 "stand": {"run": "<run id>", "cell": "<cell id>"}}
```

- `config`: exactly the four keys, with C1 values.
- `config_applied`: array of distinct axis names. Required unless all seven checks of the row are NOT_RUN.
- `config_gap`: non-empty string. Required exactly when `config_applied` lacks an axis.
- `config_how`: optional string.
- `capture_source`: `self` (the default when absent) or `stand`. `stand` is allowed only on `pass: "build"` rows, and requires the `stand` object.

### C4. Finding additions

```json
{"config_only": true, "axes": ["locale"],
 "control": {"persona": "P-02"}}
```

or `"control": {"capture": "<path>", "config": {...}}`, or `"control": {"frame": "<ref>", "config": {...}}`.

- `axes`: non-empty array of axis names.
- A `persona` control must resolve to a row in the same report with the same scenario, step, pass and round, from a different persona.
- The control's config must differ from the row's `config` on every axis in `axes`.
- `config_only` absent or false: no further fields are required.

### C5. Report top level

```json
"stand_runs": [{"run": "<run id>", "build": "<id>", "manifest": "<path>"}]
```

Required when any row has `capture_source: "stand"`. Every `stand.run` on a row must appear here.

### C6. Manifest `stand-captures/1`

```json
{"schema": "stand-captures/1", "run": "<run id>", "build": "<id>", "raw": "<path to saved door response>",
 "cells": [{"cell": "<cell id>",
            "config": {"device": "tablet", "locale": "en", "text": "largest", "theme": "dark"},
            "captures": [{"scenario": "SCR-03", "step": 2, "path": "<path>",
                          "sha256": "<64 hex>", "outcome": "<string, optional>"}]}]}
```

All relative paths in the report's new fields and in the manifest resolve against the directory of the report file.

### C7. CLI, output, exit codes

```
design_gate.py panel  <test-panel.md> [--min 10] [--json]        (flags unchanged)
design_gate.py report <design-review.json> --class <c> [existing flags] [--build <id>]
```

`--build` is an opaque string, the commit the node built from. It is compared by equality with each `stand_runs[].build` and with the manifest's `build`.

Each condition prints one line containing its code:

| Code | Verb | Result |
|---|---|---|
| `CFG-PANEL-NONE` | panel, report | warning |
| `CFG-PANEL-SYNTAX`, `CFG-PANEL-PARTIAL`, `CFG-PANEL-CELL` | panel | FAIL, exit 1 |
| `CFG-ROW-MISSING`, `CFG-ROW-MISMATCH`, `CFG-ROW-SYNTAX` | report | FAIL, exit 1 |
| `CFG-ROW-GAP` | report | `--require build` on a gated class: NOT_RUN, exit 3. Otherwise a reported count |
| `CFG-ONLY-CONTROL` | report | FAIL, exit 1 |
| `CFG-SCOPE-UNCOVERED` | report | warning, lists cells |
| `CFG-STAND-MANIFEST` (missing, unreadable, wrong schema, run or cell absent, capture not listed) | report | FAIL, exit 1 |
| `CFG-STAND-CONFIG` (cell config differs from row config) | report | FAIL, exit 1 |
| `CFG-STAND-HASH` (file missing or SHA-256 differs) | report | FAIL, exit 1 |
| `CFG-STAND-BUILD` (differs from `--build`) | report | FAIL, exit 1 |
| `CFG-STAND-NOBUILD` (stand rows, no `--build`) | report | warning |

Exit codes keep their meaning: 0 PASS, 1 FAIL, 2 usage or unreadable input, 3 NOT_RUN. Existing precedence between FAIL and NOT_RUN is unchanged.

`--json` adds one top-level key to the existing object:

```json
"config": {"panel": "present|none", "walked": [{"persona": "P-04", "config": {...}, "dir": "rtl"}],
           "gaps": 3, "uncovered": ["tablet"], "declined": ["rtl"], "stand_rows": 12}
```

### C8. `pipeline.json` → `stand` (optional)

```json
"stand": {"door": "test-stand.sshlg", "keyEnv": "TEST_STAND_CLIENT_KEY"}
```

`keyEnv` names an environment variable. The key itself never appears in the repository.

## Edge cases

- `--panel` omitted: rows' `config` objects are syntax-checked only. No mismatch check, no uncovered-cells line.
- Panel without configs but rows carry `config`: accepted and syntax-checked, with `CFG-PANEL-NONE`.
- A row fully NOT_RUN (sign-in wall): it carries `config`; `config_applied` is not required.
- The panel changed after the walk: `CFG-ROW-MISMATCH`. The affected rows are re-walked.
- A cell that is both declined and covered by a portrait: passes, no message.
- A `control.persona` equal to the row's own persona, or a control config identical on a named axis: `CFG-ONLY-CONTROL`.
- `config_applied` complete while `config_gap` is present, or a duplicate or unknown axis name: `CFG-ROW-SYNTAX`.
- `capture_source: "stand"` on a design-pass row: `CFG-ROW-SYNTAX`.
- A stand cell in the same device class at a different pixel size: equal. Class is what is compared.
- A scope whose personas cover no hard cell: the warning lists the uncovered cells. No rows are added (Q1).
- A re-review round: rows keep their persona's configuration. A control reference must be in the same round.

## Decisions

| Decision | Reason | Rejected alternative |
|---|---|---|
| One configuration per persona | Ten cells for free; the round budget is unchanged | Personas times configurations, which multiplies the matrix |
| Direction derived from locale | Removes a contradictory state | An explicit `dir` key that can disagree with the locale |
| `text` has two values | The largest size is where layouts break | A middle `large` value: more cells, few unique finds |
| `desktop` added to device classes | The tester also walks browser surfaces | Phone and tablet only, which leaves web panels inexpressible |
| No configs in a panel is a warning; partial is a fail | Mirrors the existing level rule; old panels keep passing | Failing every existing panel on release day |
| Decline line with a reason | Matches the "recorded refusal passes" doctrine | Silent omission, or hard cells with no way out |
| Gap gated in pass B, reported in pass D | Designs rarely draw ten variants; a build can be set | Gating pass D, which would demand a frame per configuration |
| Schema stays `design-review/1` | All fields are additive; old reports stay valid | `design-review/2`, which forces a migration |
| `config_only` needs a control | Otherwise the mark is a guess | A bare boolean |
| Gate reads a normalized local manifest | Independent of the stand's API; hash-checkable | The gate calling the stand's door (network, key, coupling) |
| The tester never starts stand runs | Keeps it bounded and its resource receipt honest | Trigger and wait, which is unbounded |
