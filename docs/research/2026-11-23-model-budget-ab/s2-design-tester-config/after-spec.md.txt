## Design

### The panel

`parse_panel` keeps `config` out of `FIELDS` (it stays optional) and reads it through its own alias. A new
`parse_config(value)` splits on `;`, then on the first `=`, trims, and returns the four axes or the list of
problems. `config_id(axes)` joins `device.locale.text.theme` in that fixed order with the values exactly as
written (no case folding). `direction(locale)` is `rtl` for `pseudo-rtl` or a primary language subtag in
`ar`, `he`, `fa`, `ur`, else `ltr`. `edges(axes)` returns the subset of the six edge values the
configuration carries: `phone-small` or `tablet` from device, `rtl` from the derived direction,
`pseudo-double` from locale, `largest` from text, `dark` from theme.

`panel_problems` gains the level rule of D2 and the coverage rules of R3; `panel_notes` gains the
config-less warning and one `waived: <edge> (<reason>)` line per waiver. The waiver line is read only
before the first `## P-` heading.

### The report

`report_check` reads the panel's configs once. When every portrait has one, it runs the config contracts
(R7 to R11) and adds their problems to the existing list, so the existing FAIL and NOT_RUN order holds:
problems FAIL first, then the coverage gap, then edge coverage NOT_RUN (R11), then the existing per-pass
NOT_RUN. When no portrait has one and the report carries any config field, it fails (D1: configurations
are fixed in the panel, not chosen at run time). When the panel is partly configured, it fails and names
`design_gate.py panel`. Without `--panel`, the config contracts that need the panel are not computed and a
note says so, as coverage is today.

The edge values a report owes are the non-waived edge values carried by personas that use at least one
scope scenario; an edge carried by no in-scope persona is a note, `not reached by this scope: <edge>`
(Questions Q3).

### The tester's walk

Before a persona's first step the tester sets the persona's configuration and records it in
`configurations`: the viewport (the class's default, or a real device's width inside the band), the locale
or pseudo-locale, the text size and the theme, by the platform tables in Contracts. On the web: the
driver's viewport and locale, `dir="rtl"` on the root for `pseudo-rtl`, a root font of 130% or 200%, the
driver's color-scheme emulation where it has one, else the product's own theme setting; `pseudo-double`
injects a script that repeats each visible text node's text twice, joined by a space, on load and on DOM
mutation, skipping `script`, `style` and form values. A finding reached only through that script says so in
its `what`. What the build cannot produce is a `config_gap` on that axis, the step walked without it.

`needs` stays as prose; where it disagrees with `config`, `config` governs the walk (D13).

A config-only finding: the defect shows in the persona's configuration and is absent at the same scenario
step in the reference. The reference capture is the `capture` of a zero-edge persona's row at that
scenario, step and pass when one exists, and the reference is then that row's config; otherwise the tester
takes one extra capture in `reference_config` for that finding (not a row, not a second pass), and the
reference is `reference_config`. `reference_config` is the configuration of the zero-edge persona that uses
the most scope scenarios. Within the axes that differ, which axis caused the defect is the tester's
judgement (D9).

Pass D: a frame is usually drawn in one configuration. The row names the persona's config and
`frame_in_config`; when it is false the tester judges `text_fit` and `controls` by reasoning and does not
mark a finding config-only.

### Row B: stand captures

For mobile nodes the build pass may fill a row from a stand run that already exists, read through the
stand door with the design-tester's own client key (D17); the tester never starts, schedules or configures
a run, and stand runs are not entered in the resource guard ledger (D18). Only manifest entries with a
scenario and a step fill a row (D14); an untagged `explore` capture can be attached to a finding as
`stand_evidence` and nothing more. `design_gate.py report` takes `--stand-manifest <file>`, repeatable, one
file per run.

## Contracts

### Vocabulary

| Axis | Key in the panel line | Values | Edge values |
|---|---|---|---|
| device | `device` | `phone-small`, `phone-large`, `tablet`, `desktop` | `phone-small`, `tablet` |
| locale | `locale` | a BCP 47 tag, `pseudo-rtl`, `pseudo-double` | `rtl` (derived direction), `pseudo-double` |
| text | `text` | `default`, `large`, `largest` | `largest` |
| theme | `theme` | `light`, `dark` | `dark` |

- A BCP 47 tag here is `language[-Script][-REGION]`: 2 or 3 lowercase letters, an optional 4-letter
  title-case script, an optional 2-letter uppercase or 3-digit region (`en-US`, `ar`, `zh-Hant-TW`).
  The platform realizations `en-XA` and `ar-XB` are refused in the panel: it writes `pseudo-double` and
  `pseudo-rtl`.
- Direction: `rtl` for `pseudo-rtl` or primary language `ar`, `he`, `fa`, `ur`; otherwise `ltr`.
- Axis names in `config_gap.axis` and `config_axes` are `device`, `locale`, `text`, `theme`.

### Device bands (CSS px or points, portrait)

| Class | Width band | Default viewport |
|---|---|---|
| `phone-small` | ≤ 375 | 360x640 |
| `phone-large` | 390 to 430 | 430x932 |
| `tablet` | 744 to 1024 | 820x1180 |
| `desktop` | ≥ 1280 | 1440x900 |

A width between bands (376 to 389, 431 to 743, 1025 to 1279) belongs to no class.

### Text size and pseudo-locale per platform

| Value | iOS | Android | Web |
|---|---|---|---|
| `default` | Dynamic Type Large (system default) | font scale 1.0 | root font 100% |
| `large` | Dynamic Type xxxLarge | font scale 1.3 | root font 130% |
| `largest` | Dynamic Type AX5 | font scale 2.0 | root font 200% |
| `pseudo-rtl` | Right-to-Left Pseudolanguage | `ar-XB` | `dir="rtl"` on the root |
| `pseudo-double` | Double-Length Pseudolanguage | `en-XA` | each text node doubled by a script injected in the tester's browser |

Android `en-XA` lengthens text but does not double it: its `configurations` entry carries
`"approximation": "en-XA lengthens, does not double"`.

### Panel

Syntax (a fragment, not a whole panel):

```markdown
# Test panel

Configurations not owed: dark (the product ships one theme until v2)

## P-01 Persona 1
- **config**: device=phone-small; locale=pseudo-rtl; text=default; theme=light
```

The waiver line is optional, one per panel, before the first portrait; each item is `<edge> (<reason>)`,
items separated by commas, the edge one of the six, the reason non-empty and free of parentheses.

`design_gate.py panel` on a configured panel:

- every `config` line parses to the four axes with values in the vocabulary;
- the device and locale tokens are valid;
- the set of edge values across portraits, plus the waived set, equals the six;
- the per-persona edge count is ≤ 2;
- the count of zero-edge personas is ≥ 2;
- every waiver has a non-empty reason.

### Report checks when the panel carries configs

- **Row config.** For every row, `row.config` equals the id computed from that persona's panel line
  (string equality), and that id is a key of `configurations`.
- **Configurations block.** For each entry: its `device`, `locale`, `text_size`, `theme` equal the parse of
  its id; `direction` equals the derived direction; the viewport width lies in the band of its device
  class; an `approximation`, when present, is a non-empty string.
- **Reference.** `reference_config` resolves in `configurations` and has zero edge values.
- **Pass D.** Every design row carries `frame_in_config` as a boolean.
- **Config-only finding.** For `only_in_config: true`:
  - `item` is one of the seven checklist items and that item is `fail` in the row;
  - `config_axes` is non-empty, each a known axis name, none equal to the row's `config_gap.axis`;
  - `reference_capture` resolves to an existing file; when it equals another row's `capture`, that row has
    the same scenario, step and pass and a config with zero edge values, and the reference is that row's
    config; otherwise the reference is `reference_config`;
  - every named axis has different values in the row's config and the reference;
  - no zero-edge row with the same scenario, step and pass has `checks[item] == "fail"`, otherwise the
    finding is refused as contradicted;
  - in pass D, `frame_in_config` is true.
- **Finding completeness.** Every finding in a build-pass row whose config has at least one edge value
  carries `only_in_config` as an explicit boolean.
- **config_gap.** `axis` is a known axis name and `reason` is non-empty.
- **Edge coverage**, `--require build`: each owed edge value has at least one build row whose config
  carries it, without a `config_gap` on that edge's axis and with at least one check that is not NOT_RUN.
  If not: NOT_RUN (exit 3) on `flagship`, `product`, `ad`; a note on `internal`.

Exit codes are unchanged: 0 PASS, 1 FAIL, 2 usage or unreadable input, 3 NOT_RUN.

### Row B: the manifest asked of the stand, and the stand-capture check

```json
{"run": "<run id>", "build": "<40-hex commit sha>",
 "entries": [{"scenario": "SCR-03", "step": 2,
              "cell": {"device_width": 360, "locale": "ar-XB", "text_size": "1.0", "theme": "light"},
              "sha256": "<64-hex>", "assertion": {"text": "order exists in history", "result": "pass"}}]}
```

`assertion` is `{text, result}` with `result` `pass` or `fail`, or `null` when the step had no scripted
assertion. A cell maps to a config id through the tables above: `device_width` to the class whose band
holds it; `locale` `ar-XB` or the iOS Right-to-Left Pseudolanguage to `pseudo-rtl`, `en-XA` or the iOS
Double-Length Pseudolanguage to `pseudo-double`, any other BCP 47 tag to itself; `text_size` from the
platform value to `default`, `large`, `largest`; `theme` as is. A value with no mapping is a mismatch.

For a row with `capture_source: "stand"`:

- the sha256 of the file at `capture` equals `capture_sha256` and equals the manifest entry's `sha256`;
- the manifest's `run` equals the row's `stand_run`;
- the manifest's `build` equals the report's `node_commit`, which resolves to a commit in the repository
  the gate runs in;
- the entry's scenario and step equal the row's, and the entry carries both;
- the entry's cell, mapped, equals the row's config on all four axes;
- `checks.outcome` is `pass` only when the entry's `assertion.result` is `pass` and `assertion.text`
  appears verbatim in the row's `outcome`, or the row carries `outcome_read_back: true`; otherwise it is
  NOT_RUN with a reason, or `fail` when the assertion failed.

Any mismatch is FAIL. A stand row with no `--stand-manifest` for its run is NOT_RUN with that reason. A
`stand_evidence` item's file hash equals its `capture_sha256` and an entry's `sha256` in that run's
manifest, or the finding fails.

The stand client key is read through the project's secret runner as `TEST_STAND_CLIENT_KEY` under the
design-tester's own sender identity, in the environment only, never on a command line or printed.

### Backward compatibility

A config-less panel with a report that has no config fields produces the same exit code as before the
change, proved by the existing fixtures run unchanged (R12).

## Edge cases

| Case | Behaviour |
|---|---|
| Config-less panel | `panel` warns, exit unchanged; `report` runs as today |
| Config-less panel, report with config fields | FAIL: configurations are fixed in the panel (D1) |
| Nine of ten portraits configured | `panel` and `report` FAIL, naming the persona without one |

## Decisions

| id | decision | reason |
|---|---|---|
| D1 | One configuration per persona, fixed in the panel and not chosen per run. | The matrix must stay scenarios × personas, and a config chosen at run time is not reproducible across rounds. |
| D2 | The panel `config` line is opt-in at panel level, following the gate's existing level rule: none, warning and exit unchanged; some, FAIL; all, the coverage rules apply. | Existing panels and reports must keep passing until super-ux revises the template. |
| D3 | The schema stays `design-review/1` with additive fields. | The brief names that schema, and a config-less panel with an old report must pass byte-for-byte as before. |
| D4 | When the panel carries configs, `report` enforces the config contracts automatically, with no new flag. | An optional flag is a check nobody passes. |
| D5 | The checklist stays at seven items; configuration defects land in `text_fit`, `controls`, `primary_action`, `states` or `focus`. | An eighth item would invalidate every existing report. |
| D6 | `desktop` is a fourth device class and is not an edge value. | The tester's browser pass is desktop web today, and a desktop product must not be forced into phone portraits only. |
| D7 | A persona carries at most two edge values and two personas carry none. | A failure under four stacked edge values cannot be attributed to one, and zero-edge personas give free reference captures. |
| D8 | `only_in_config: true` requires a reference capture and named axes. | "Only here" is a comparison claim and needs its other side. |
| D9 | Axis attribution within the differing axes is the tester's judgement; the gate checks only that named axes differ from the reference. | Isolating one axis would need a capture per axis, which the budget forbids. |
| D10 | A configuration the build cannot produce is a `config_gap`, the step walked without that axis; an owed edge value with no gap-free build row makes the gate NOT_RUN (exit 3) on gated classes and is reported on `internal`. | A silent fallback to the reference would read as covered. |
| D11 | Waivers live in the panel with a reason, and the gate prints them. | Whether a product owes RTL or dark is a product fact that the panel's confirmer owns. |
| D12 | Edge coverage is enforced only with `--require build`; with `--require design` the config ids are checked but coverage is not. | Frames rarely exist per configuration. |
| D13 | The prose `needs` line stays, and `config` governs the walk where they disagree. | `needs` is free text and `config` is checkable. |
| D14 | Stand captures fill a row only when the manifest entry carries a scenario id and step; untagged `explore` captures are finding evidence and nothing more. | A row is a claim about one step. |
| D15 | A stand capture is used only when its build id equals the node's commit sha under review and its cell maps to the persona's config on all four axes. | A screenshot of another build or another cell is evidence about something else. |
| D16 | With a stand capture, `outcome` is `pass` only when the manifest carries the scripted assertion result for that step, quoted in the row, or the tester reads the outcome back itself; otherwise NOT_RUN with a reason. | A screenshot does not prove the order exists. |
| D17 | The stand client key is read through the project's secret runner under the design-tester's own sender identity, never on a command line or printed. | The stand keys per sender, and this is the existing Figma token rule. |
| D18 | Stand runs are not entered in the resource guard ledger. | The tester did not start them, and the receipt covers only what it started. |
| D19 | Row B is separate and does not block Row A. | The stand's manifest is not ours to ship, and item 1 has value alone. |
| D20 | `agent-tester` is unchanged. | It judges agent surfaces, which have no device configuration. |
| D21 | The super-ux panel template change is a cross-repository board row filed with Row A, not done here. | super-ux owns the template. |

## Risks

- **Stacked axes hide the cause.** If most config-only findings name two axes, attribution is too coarse:
  move to one edge value per persona.
- **Web pseudo-double is synthetic.** Doubling text nodes may break layouts that real long locales would
  not; findings reached only this way say so in `what`.
- **Unproduced configurations block the gate.** Products that cannot switch theme or locale in the build
  go NOT_RUN until they are waived, so expect waiver pressure.
- **The stand's manifest may lack scenario tags or build ids.** Row B then delivers nothing, and native
  mobile pass B stays NOT_RUN as it is today.
- **Refutation.** The design is wrong if, after three reviewed nodes, zero findings are marked config-only
  while the stand finds configuration bugs on the same builds.
