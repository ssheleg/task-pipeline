## Design

### The panel

`parse_panel` keeps `config` out of `FIELDS` (it stays optional) and reads it through its own alias. A new
`parse_config(value)` splits on `;`, then on the first `=`, trims, and returns the four axes or the list of
problems. `config_id(axes)` joins `device.locale.text.theme` in that fixed order with the values exactly as
written (no case folding). `direction(locale)` is `rtl` for `pseudo-rtl` or a primary language subtag in
`ar`, `he`, `fa`, `ur`, else `ltr`. `edges(axes)` returns the subset of the six edge values the
configuration carries: `phone-small` or `tablet` from device, `rtl` from the derived direction,
`pseudo-double` from locale, `largest` from text, `dark` from theme.

`panel_problems` gains the level rule of D2 and the coverage rules of R3; `panel_notes` gains the
config-less warning and one `waived: <edge> (<reason>)` line per waiver. The waiver line is read only
before the first `## P-` heading.

### The report

`report_check` reads the panel's configs once. When every portrait has one, it runs the config contracts
(R7 to R11) and adds their problems to the existing list, so the existing FAIL and NOT_RUN order holds:
problems FAIL first, then the coverage gap, then edge coverage NOT_RUN (R11), then the existing per-pass
NOT_RUN. When no portrait has one and the report carries any config field, it fails (D1: configurations
are fixed in the panel, not chosen at run time). When the panel is partly configured, it fails and names
`design_gate.py panel`. Without `--panel`, the config contracts that need the panel are not computed and a
note says so, as coverage is today.

The edge values a report owes are the non-waived edge values carried by personas that use at least one
scope scenario; an edge carried by no in-scope persona is a note, `not reached by this scope: <edge>`
(Questions Q3).

### The tester's walk

Before a persona's first step the tester sets the persona's configuration and records it in
`configurations`: the viewport (the class's default, or a real device's width inside the band), the locale
or pseudo-locale, the text size and the theme, by the platform tables in Contracts. On the web: the
driver's viewport and locale, `dir="rtl"` on the root for `pseudo-rtl`, a root font of 130% or 200%, the
driver's color-scheme emulation where it has one, else the product's own theme setting; `pseudo-double`
injects a script that repeats each visible text node's text twice, joined by a space, on load and on DOM
mutation, skipping `script`, `style` and form values. A finding reached only through that script says so in
its `what`. What the build cannot produce is a `config_gap` on that axis, the step walked without it.

`needs` stays as prose; where it disagrees with `config`, `config` governs the walk (D13).

A config-only finding: the defect shows in the persona's configuration and is absent at the same scenario
step in the reference. The reference capture is the `capture` of a zero-edge persona's row at that
scenario, step and pass when one exists, and the reference is then that row's config; otherwise the tester
takes one extra capture in `reference_config` for that finding (not a row, not a second pass), and the
reference is `reference_config`. `reference_config` is the configuration of the zero-edge persona that uses
the most scope scenarios. Within the axes that differ, which axis caused the defect is the tester's
judgement (D9).

Pass D: a frame is usually drawn in one configuration. The row names the persona's config and
`frame_in_config`; when it is false the tester judges `text_fit` and `controls` by reasoning and does not
mark a finding config-only.

### Row B: stand captures

For mobile nodes the build pass may fill a row from a stand run that already exists, read through the
stand door with the design-tester's own client key (D17); the tester never starts, schedules or configures
a run, and stand runs are not entered in the resource guard ledger (D18). Only manifest entries with a
scenario and a step fill a row (D14); an untagged `explore` capture can be attached to a finding as
`stand_evidence` and nothing more. `design_gate.py report` takes `--stand-manifest <file>`, repeatable, one
file per run.

## Contracts

### Vocabulary

| Axis | Key in the panel line | Values | Edge values |
|---|---|---|---|
| device | `device` | `phone-small`, `phone-large`, `tablet`, `desktop` | `phone-small`, `tablet` |
| locale | `locale` | a BCP 47 tag, `pseudo-rtl`, `pseudo-double` | `rtl` (derived direction), `pseudo-double` |
| text | `text` | `default`, `large`, `largest` | `largest` |
| theme | `theme` | `light`, `dark` | `dark` |

- A BCP 47 tag here is `language[-Script][-REGION]`: 2 or 3 lowercase letters, an optional 4-letter
  title-case script, an optional 2-letter uppercase or 3-digit region (`en-US`, `ar`, `zh-Hant-TW`).
  The platform realizations `en-XA` and `ar-XB` are refused in the panel: it writes `pseudo-double` and
  `pseudo-rtl`.
- Direction: `rtl` for `pseudo-rtl` or primary language `ar`, `he`, `fa`, `ur`; otherwise `ltr`.
- Axis names in `config_gap.axis` and `config_axes` are `device`, `locale`, `text`, `theme`.

### Device bands (CSS px or points, portrait)

| Class | Width band | Default viewport |
|---|---|---|
| `phone-small` | ≤ 375 | 360x640 |
| `phone-large` | 390 to 430 | 430x932 |
| `tablet` | 744 to 1024 | 820x1180 |
| `desktop` | ≥ 1280 | 1440x900 |

A width between bands (376 to 389, 431 to 743, 1025 to 1279) belongs to no class.

### Text size and pseudo-locale per platform

| Value | iOS | Android | Web |
|---|---|---|---|
| `default` | Dynamic Type Large (system default) | font scale 1.0 | root font 100% |
| `large` | Dynamic Type xxxLarge | font scale 1.3 | root font 130% |
| `largest` | Dynamic Type AX5 | font scale 2.0 | root font 200% |
| `pseudo-rtl` | Right-to-Left Pseudolanguage | `ar-XB` | `dir="rtl"` on the root |
| `pseudo-double` | Double-Length Pseudolanguage | `en-XA` | each text node doubled by a script injected in the tester's browser |

Android `en-XA` lengthens text but does not double it: its `configurations` entry carries
`"approximation": "en-XA lengthens, does not double"`.

### Panel

Syntax (a fragment, not a whole panel):

```markdown
# Test panel

Configurations not owed: dark (the product ships one theme until v2)

## P-01 Persona 1
- **config**: device=phone-small; locale=pseudo-rtl; text=default; theme=light
```

The waiver line is optional, one per panel, before the first portrait; each item is `<edge> (<reason>)`,
items separated by commas, the edge one of the six, the reason non-empty and free of parentheses.

`design_gate.py panel` on a configured panel:

- every `config` line parses to the four axes with values in the vocabulary;
- the device and locale tokens are valid;
- the set of edge values across portraits, plus the waived set, equals the six;
- the per-persona edge count is ≤ 2;
- the count of zero-edge personas is ≥ 2;
- every waiver has a non-empty reason.

### Report checks when the panel carries configs

- **Row config.** For every row, `row.config` equals the id computed from that persona's panel line
  (string equality), and that id is a key of `configurations`.
- **Configurations block.** For each entry: its `device`, `locale`, `text_size`, `theme` equal the parse of
  its id; `direction` equals the derived direction; the viewport width lies in the band of its device
  class; an `approximation`, when present, is a non-empty string.
- **Reference.** `reference_config` resolves in `configurations` and has zero edge values.
- **Pass D.** Every design row carries `frame_in_config` as a boolean.
- **Config-only finding.** For `only_in_config: true`:
  - `item` is one of the seven checklist items and that item is `fail` in the row;
  - `config_axes` is non-empty, each a known axis name, none equal to the row's `config_gap.axis`;
  - `reference_capture` resolves to an existing file; when it equals another row's `capture`, that row has
    the same scenario, step and pass and a config with zero edge values, and the reference is that row's
    config; otherwise the reference is `reference_config`;
  - every named axis has different values in the row's config and the reference;
  - no zero-edge row with the same scenario, step and pass has `checks[item] == "fail"`, otherwise the
    finding is refused as contradicted;
  - in pass D, `frame_in_config` is true.
- **Finding completeness.** Every finding in a build-pass row whose config has at least one edge value
  carries `only_in_config` as an explicit boolean.
- **config_gap.** `axis` is a known axis name and `reason` is non-empty.
- **Edge coverage**, `--require build`: each owed edge value has at least one build row whose config
  carries it, without a `config_gap` on that edge's axis and with at least one check that is not NOT_RUN.
  If not: NOT_RUN (exit 3) on `flagship`, `product`, `ad`; a note on `internal`.

Exit codes are unchanged: 0 PASS, 1 FAIL, 2 usage or unreadable input, 3 NOT_RUN.

### Row B: the manifest asked of the stand, and the stand-capture check

```json
{"run": "<run id>", "build": "<40-hex commit sha>",
 "entries": [{"scenario": "SCR-03", "step": 2,
              "cell": {"device_width": 360, "locale": "ar-XB", "text_size": "1.0", "theme": "light"},
              "sha256": "<64-hex>", "assertion": {"text": "order exists in history", "result": "pass"}}]}
```

`assertion` is `{text, result}` with `result` `pass` or `fail`, or `null` when the step had no scripted
assertion. A cell maps to a config id through the tables above: `device_width` to the class whose band
holds it; `locale` `ar-XB` or the iOS Right-to-Left Pseudolanguage to `pseudo-rtl`, `en-XA` or the iOS
Double-Length Pseudolanguage to `pseudo-double`, any other BCP 47 tag to itself; `text_size` from the
platform value to `default`, `large`, `largest`; `theme` as is. A value with no mapping is a mismatch.

For a row with `capture_source: "stand"`:

- the sha256 of the file at `capture` equals `capture_sha256` and equals the manifest entry's `sha256`;
- the manifest's `run` equals the row's `stand_run`;
- the manifest's `build` equals the report's `node_commit`, which resolves to a commit in the repository
  the gate runs in;
- the entry's scenario and step equal the row's, and the entry carries both;
- the entry's cell, mapped, equals the row's config on all four axes;
- `checks.outcome` is `pass` only when the entry's `assertion.result` is `pass` and `assertion.text`
  appears verbatim in the row's `outcome`, or the row carries `outcome_read_back: true`; otherwise it is
  NOT_RUN with a reason, or `fail` when the assertion failed.

Any mismatch is FAIL. A stand row with no `--stand-manifest` for its run is NOT_RUN with that reason. A
`stand_evidence` item's file hash equals its `capture_sha256` and an entry's `sha256` in that run's
manifest, or the finding fails.

The stand client key is read through the project's secret runner as `TEST_STAND_CLIENT_KEY` under the
design-tester's own sender identity, in the environment only, never on a command line or printed.

### Backward compatibility

A config-less panel with a report that has no config fields produces the same exit code as before the
change, proved by the existing fixtures run unchanged (R12).

## Edge cases

| Case | Behaviour |
|---|---|
| Config-less panel | `panel` warns, exit unchanged; `report` runs as today |
| Config-less panel, report with config fields | FAIL: configurations are fixed in the panel (D1) |
| Nine of ten portraits configured | `panel` and `report` FAIL, naming the persona without one |
| `needs` says "iPad" while `config` says `phone-small` | the walk follows `config` (D13); no gate finding |
| Persona with three edge values | FAIL, naming the persona and the three |
| Edge value both carried and waived | passes; the waiver still prints |

| `frame_in_config: false` and a text overflow drawn only for the frame's config | judged by reasoning; the finding may not be config-only |

| Web `pseudo-double` breaks a layout | the finding's `what` says it was reached only through the injected script |
| Viewport width 380 | in no band: FAIL for every class |
| Stand manifest entry without scenario or step | cannot fill a row (FAIL if used); may be `stand_evidence` on a finding |
| Stand manifest of another build | FAIL on every row it fills |

| D1 | One configuration per persona, fixed in the panel and not chosen per run. | The matrix must stay scenarios × personas, and a config chosen at run time is not reproducible across rounds. |

## Risks

- **Stacked axes hide the cause.** If most config-only findings name two axes, attribution is too coarse:
  move to one edge value per persona.
- **Web pseudo-double is synthetic.** Doubling text nodes may break layouts that real long locales would
  not; findings reached only this way say so in `what`.
- **Unproduced configurations block the gate.** Products that cannot switch theme or locale in the build
  go NOT_RUN until they are waived, so expect waiver pressure.
- **The stand's manifest may lack scenario tags or build ids.** Row B then delivers nothing, and native
  mobile pass B stays NOT_RUN as it is today.
- **Refutation.** The design is wrong if, after three reviewed nodes, zero findings are marked config-only
  while the stand finds configuration bugs on the same builds.

## Design

### One configuration per persona

A configuration has four axes: `device`, `locale`, `text`, `theme`. Direction is derived from the locale and never written, so the two cannot disagree. Each portrait holds exactly one configuration. Ten personas therefore give ten cells at no extra matrix cost. The hard cells are spread across the panel, and the panel gate checks that the spread exists.

The `needs` line stays prose about the person. `config` is the normative test configuration. The gate does not cross-check the two.

### Direction, derived

`dir(locale)` is `rtl` when:
- the locale is `pseudo-rtl`; or
- its second subtag is a four-letter script in {Arab, Hebr, Thaa, Syrc, Nkoo}; or
- it has no four-letter script subtag and its primary subtag is in {ar, he, fa, ur, ps, sd, yi, dv, ckb, ug}.

Otherwise it is `ltr`. An explicit other script wins: `sd-Deva` is ltr.

### What "applied" means

- Pass B: an axis is applied when the environment that produced the capture was set to the persona's value, default values included. If the app ignores the setting (no dark theme exists), the axis is still applied; whether that is a finding is the tester's judgment.
- Pass D: an axis is applied when the frame or mockup read was drawn at the persona's value. Most designs draw one variant, so gaps are normal there. The tester still judges `text_fit` and `controls` for the persona's configuration by reasoning, and says so in the finding's `what`.

An approximation counts as applied only if it appears in the table below, and the row names it in `config_how`.

### Realizing a value

This table is guidance for whoever captures (a stand cell or the tester). It goes into `references/design-review.md`. The gate checks none of it. Tool flags are to be confirmed against the installed versions (Q9).

| Value | iOS simulator | Android | Browser |
|---|---|---|---|
| `small-phone` (shorter side up to 375) | a model in class | a profile in class | viewport 360x640 |
| `large-phone` (shorter side 376 to 599) | a model in class | a profile in class | viewport 430x932 |
| `tablet` (shorter side 600 or more) | an iPad | a tablet profile | viewport 820x1180 |
| `desktop` | not applicable | not applicable | viewport 1440x900 |
| `pseudo-rtl` | launch args `-AppleTextDirection YES -NSForceRightToLeftWritingDirection YES` | locale `ar-XB`, pseudolocales enabled in the build | the project's RTL pseudo-locale, else `dir="rtl"` on the root element (approximation) |
| `pseudo-double` | launch arg `-NSDoubleLocalizedStrings YES` | locale `en-XA` (approximation: lengthened, not doubled) | the project's pseudo-locale, else a gap |
| `largest` | `xcrun simctl ui <device> content_size accessibility-extra-extra-extra-large` | `adb shell settings put system font_scale 2.0` | the driver's 200% text or minimum font size setting, else a gap |
| `dark` | `xcrun simctl ui <device> appearance dark` | `adb shell cmd uimode night yes` | the driver's `prefers-color-scheme: dark` emulation, else a gap |

### "Only in this configuration"

A finding is config-only when a control look at the same scenario step does not show it, and the control's configuration differs on the axes blamed. The cheapest control is another persona's row for the same step in the same pass. Failing that, the tester takes one extra capture or frame, at most one per finding. Without a control the finding is still reported; it just does not carry `config_only`.

### Stand intake (mobile nodes, pass B)

1. `pipeline.json` gains an optional `stand` block (C8). If it is absent, this path does not exist and the tester captures as today.
2. The tester asks the stand's door for a finished run of the node's build. The call runs under the project's secret runner with the client key in the environment, never on the command line or printed. It does not start a run and does not poll. No finished run for this build means self-capture.
3. It saves the door's raw response and the screenshots beside its own captures. It then writes a normalized manifest (C6) next to the report as `<report-stem>.stand-<run>.json`.
4. A stand capture serves a row only if the stand tagged it with that scenario and step and its cell's configuration equals the persona's on all four axes. Untagged `explore` screenshots serve no row.
5. The `outcome` check uses the outcome the stand recorded for that capture, if any. Otherwise the tester reads the outcome back itself or sets `outcome` to NOT_RUN with the reason `stand capture carries no outcome`.
6. Rows with no matching cell fall back to self-capture. If there is no local channel either, the row is NOT_RUN with that reason.

The exact door verbs are not known from the brief (Q5). The gate depends only on the local manifest, so it is buildable now. The agent's fetch step ships in phase 2 once the door contract is confirmed.

## Contracts

### C1. Panel `config` field

Written with the same field markup the parser already accepts for `needs`. The implementer reuses that extraction and does not add a second syntax. Value:

```
device=<small-phone|large-phone|tablet|desktop>; locale=<tag>; text=<default|largest>; theme=<light|dark>
```

- Four `key=value` pairs separated by `;`, in any order, each key exactly once, whitespace trimmed.
- `locale` is `pseudo-rtl`, `pseudo-double`, or matches `^[a-z]{2,3}(-[A-Za-z0-9]{2,8})*$`.
- Any violation is `CFG-PANEL-SYNTAX` (FAIL), naming the portrait and the key.

### C2. Hard cells and declines

| Cell | Satisfied by a portrait with |
|---|---|
| `rtl` | derived direction rtl |
| `double-length` | `locale=pseudo-double` |
| `largest-text` | `text=largest` |
| `dark` | `theme=dark` |
| `small-screen` | `device=small-phone` |
| `tablet` | `device=tablet` |

Decline line: anywhere in the panel file, after stripping a leading `- ` and whitespace, matching `^Config declined: (rtl|double-length|largest-text|dark|small-screen|tablet): (\S.*)$`. A line starting `Config declined:` that does not match is `CFG-PANEL-SYNTAX`.

### C3. Row additions (`design-review/1`, additive, schema string unchanged)

```json
{"config": {"device": "small-phone", "locale": "pseudo-rtl", "text": "default", "theme": "light"},
 "config_applied": ["device", "locale", "text", "theme"],
 "config_gap": "no dark variant of this frame",
 "config_how": "dir=rtl on the root element",
 "capture_source": "self",
 "stand": {"run": "<run id>", "cell": "<cell id>"}}
```

- `config`: exactly the four keys, with C1 values.
- `config_applied`: array of distinct axis names. Required unless all seven checks of the row are NOT_RUN.
- `config_gap`: non-empty string. Required exactly when `config_applied` lacks an axis.
- `config_how`: optional string.
- `capture_source`: `self` (the default when absent) or `stand`. `stand` is allowed only on `pass: "build"` rows, and requires the `stand` object.

### C4. Finding additions

```json
{"config_only": true, "axes": ["locale"],
 "control": {"persona": "P-02"}}
```

or `"control": {"capture": "<path>", "config": {...}}`, or `"control": {"frame": "<ref>", "config": {...}}`.

- `axes`: non-empty array of axis names.
- A `persona` control must resolve to a row in the same report with the same scenario, step, pass and round, from a different persona.
- The control's config must differ from the row's `config` on every axis in `axes`.
- `config_only` absent or false: no further fields are required.

### C5. Report top level

```json
"stand_runs": [{"run": "<run id>", "build": "<id>", "manifest": "<path>"}]
```

Required when any row has `capture_source: "stand"`. Every `stand.run` on a row must appear here.

### C6. Manifest `stand-captures/1`

```json
{"schema": "stand-captures/1", "run": "<run id>", "build": "<id>", "raw": "<path to saved door response>",
 "cells": [{"cell": "<cell id>",
            "config": {"device": "tablet", "locale": "en", "text": "largest", "theme": "dark"},
            "captures": [{"scenario": "SCR-03", "step": 2, "path": "<path>",
                          "sha256": "<64 hex>", "outcome": "<string, optional>"}]}]}
```

All relative paths in the report's new fields and in the manifest resolve against the directory of the report file.

### C7. CLI, output, exit codes

```
design_gate.py panel  <test-panel.md> [--min 10] [--json]        (flags unchanged)
design_gate.py report <design-review.json> --class <c> [existing flags] [--build <id>]
```

`--build` is an opaque string, the commit the node built from. It is compared by equality with each `stand_runs[].build` and with the manifest's `build`.

Each condition prints one line containing its code:

| Code | Verb | Result |
|---|---|---|
| `CFG-PANEL-NONE` | panel, report | warning |
| `CFG-PANEL-SYNTAX`, `CFG-PANEL-PARTIAL`, `CFG-PANEL-CELL` | panel | FAIL, exit 1 |
| `CFG-ROW-MISSING`, `CFG-ROW-MISMATCH`, `CFG-ROW-SYNTAX` | report | FAIL, exit 1 |
| `CFG-ROW-GAP` | report | `--require build` on a gated class: NOT_RUN, exit 3. Otherwise a reported count |
| `CFG-ONLY-CONTROL` | report | FAIL, exit 1 |
| `CFG-SCOPE-UNCOVERED` | report | warning, lists cells |
| `CFG-STAND-MANIFEST` (missing, unreadable, wrong schema, run or cell absent, capture not listed) | report | FAIL, exit 1 |
| `CFG-STAND-CONFIG` (cell config differs from row config) | report | FAIL, exit 1 |
| `CFG-STAND-HASH` (file missing or SHA-256 differs) | report | FAIL, exit 1 |
| `CFG-STAND-BUILD` (differs from `--build`) | report | FAIL, exit 1 |
| `CFG-STAND-NOBUILD` (stand rows, no `--build`) | report | warning |

Exit codes keep their meaning: 0 PASS, 1 FAIL, 2 usage or unreadable input, 3 NOT_RUN. Existing precedence between FAIL and NOT_RUN is unchanged.

`--json` adds one top-level key to the existing object:

```json
"config": {"panel": "present|none", "walked": [{"persona": "P-04", "config": {...}, "dir": "rtl"}],
           "gaps": 3, "uncovered": ["tablet"], "declined": ["rtl"], "stand_rows": 12}
```

### C8. `pipeline.json` → `stand` (optional)

```json
"stand": {"door": "test-stand.sshlg", "keyEnv": "TEST_STAND_CLIENT_KEY"}
```

`keyEnv` names an environment variable. The key itself never appears in the repository.

## Edge cases

- `--panel` omitted: rows' `config` objects are syntax-checked only. No mismatch check, no uncovered-cells line.
- Panel without configs but rows carry `config`: accepted and syntax-checked, with `CFG-PANEL-NONE`.
- A row fully NOT_RUN (sign-in wall): it carries `config`; `config_applied` is not required.
- The panel changed after the walk: `CFG-ROW-MISMATCH`. The affected rows are re-walked.
- A cell that is both declined and covered by a portrait: passes, no message.
- A `control.persona` equal to the row's own persona, or a control config identical on a named axis: `CFG-ONLY-CONTROL`.
- `config_applied` complete while `config_gap` is present, or a duplicate or unknown axis name: `CFG-ROW-SYNTAX`.
- `capture_source: "stand"` on a design-pass row: `CFG-ROW-SYNTAX`.
- A stand cell in the same device class at a different pixel size: equal. Class is what is compared.
- A scope whose personas cover no hard cell: the warning lists the uncovered cells. No rows are added (Q1).
- A re-review round: rows keep their persona's configuration. A control reference must be in the same round.

## Decisions

| Decision | Reason | Rejected alternative |
|---|---|---|
| One configuration per persona | Ten cells for free; the round budget is unchanged | Personas times configurations, which multiplies the matrix |
| Direction derived from locale | Removes a contradictory state | An explicit `dir` key that can disagree with the locale |
| `text` has two values | The largest size is where layouts break | A middle `large` value: more cells, few unique finds |
| `desktop` added to device classes | The tester also walks browser surfaces | Phone and tablet only, which leaves web panels inexpressible |
| No configs in a panel is a warning; partial is a fail | Mirrors the existing level rule; old panels keep passing | Failing every existing panel on release day |
| Decline line with a reason | Matches the "recorded refusal passes" doctrine | Silent omission, or hard cells with no way out |
| Gap gated in pass B, reported in pass D | Designs rarely draw ten variants; a build can be set | Gating pass D, which would demand a frame per configuration |
| Schema stays `design-review/1` | All fields are additive; old reports stay valid | `design-review/2`, which forces a migration |
| `config_only` needs a control | Otherwise the mark is a guess | A bare boolean |
| Gate reads a normalized local manifest | Independent of the stand's API; hash-checkable | The gate calling the stand's door (network, key, coupling) |
| The tester never starts stand runs | Keeps it bounded and its resource receipt honest | Trigger and wait, which is unbounded |
